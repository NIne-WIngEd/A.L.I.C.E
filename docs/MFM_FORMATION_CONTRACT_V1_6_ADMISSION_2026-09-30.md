# MFM full-role semantics: additive 1.6 contract and admission

**State:** CPU-tested contract boundary. No trained 1.6 MFM, admitted 1.6
training corpus, independent FINAL assessment, or Stage G closure.

The ratified [identity and host-learning architecture](MEMORY_IDENTITY_FORMATION_AND_HOST_LEARNING_ARCHITECTURE.md)
defines MFM as a learned interpreter of an authorized new experience. It
proposes source-linked and time-scoped memory changes for a separate authority
gate. The comic's host learning, negotiated norms, long-running missions,
outcomes, changing preferences and shared history require more semantic output
than the currently frozen 1.5 training tier supplies. MFM does not become the
host model, personality, relationship model or the memory store.

## What 1.6 adds

`src/cognitive_kernel/formation_semantics_v16.py` defines a distinct versioned
context and output around the existing 1.5 records. It binds:

| Added field | Meaning | Binding rule |
| --- | --- | --- |
| Registered source sensitivity floor and optional proposal hint | A proposal may suggest a stricter sensitivity class; no hint means unknown | A hint cannot lower the highest registered sensitivity of any cited source. The memory gate must re-read current policy before a write. |
| Episode event start/end, participant and scene references | An event interval can have one unknown endpoint; participants and overlapping scenes are explicit links | Episode kind requires event semantics. Every linked entity or scene must be scoped, registered and backed by evidence cited by that proposal. |
| Relationship counterpart | Distinguishes another person from the subject whose relationship state may change | Relationship-domain proposals require a separately registered entity; self-links fail. |
| Mission and workspace target links | Connects a candidate memory to the current project and task setting | Every link must be registered in the same product, host and authority namespace, with cited supporting evidence. |

This does **not** authenticate a source, grant consent, adjudicate truth or
write a projection. Registered metadata may become stale; the independent
memory gate must resolve source and target policy again at promotion. A
proposal's source anchors still pass the exact 1.5 opened-byte grounding
check. The new evaluator compares versioned semantic fields and refuses cases
whose added dimensions lack explicit adjudication. The 1.5 evaluator rejects
a 1.6 bundle rather than dropping those fields.

## The frozen 1.5 tier remains historical evidence

The 49,819 training-only examples and their hashes are unchanged. Their absent
sensitivity, confidence, contradiction, episode, relationship, mission,
correction and source-person targets **are not negative labels**. Neither the
existing `formation_learning.py` parser/serializer nor
`train_v1_formation_specialist.py` has been upgraded to 1.6. A 1.5 candidate
can teach part of the proposal/disposition task, but cannot claim full-role
MFM readiness by scoring against its own missing fields.

The independent aggregate inspection of the exact mixture
`60fa44a5be62c8d2f0daf508e543dc1a41c34562dc0c4d399e26c9cabb772e21`
produced report SHA-256
`0f198706d5158f830c79dd3a6a891449025f453c0976f9fa21377c8cd5085cec`.
It found zero labelled sensitivity/confidence/contradiction fields and zero
episode, relationship, mission, correction or source-person proposal kinds.
That is a coverage observation, not evidence those phenomena are absent from
the fictional histories. A paid full-role fit is not admitted on this tier.

## Required corpus and integration migration

1. Freeze a new 1.6 corpus with actual source and target records, explicit
   adjudicated absence or presence for every added dimension, scoped target
   registries, original-item lineage and authenticated source sensitivity.
   Include episode boundaries, multiple scenes, different participants,
   relationship counterparts, missions/workspaces, corrections, source-person
   separation, contradictions, outcomes and abstentions across independent
   histories. Unknowns stay unknown rather than being synthesized as false.
2. Bind new train, development and sealed FINAL splits by source, person,
   family and generator lineage. Authenticate rights and two independent
   adjudications for exact targets; retain original bytes and reviewer
   receipts in authorized custody. The structural check
   `require_full_role_structural_coverage_v16` fails the historical mixture and missing
   category/split/receipt metadata. It cannot authenticate a steward, rights
   or review by itself and is not a GPU authorization receipt.
3. Implement a **separate** 1.6 processor/target serializer and loss only
   after those labels exist. Bind its objective, tokenizer, model artifact,
   split digest and evaluator to the version. Keep the 1.5 read path and
   reproducibility intact; do not rewrite 1.5 targets or reinterpret absent
   fields as negatives.
4. Connect registered source policy and target resolution to the context
   planner, memory gate and projection managers. Test stale/revoked/cross-host
   targets, source policy escalation, source-person identity, event revisions,
   correction/deletion rebuild, and downstream native judgment separately.
   No schema test or training loss alone demonstrates comic-level behavior.

The next paid full-role fit therefore waits for a new admitted and adjudicated
1.6 tier plus measured processor/backward feasibility. The existing 1.5
specialist route remains a bounded learning experiment with its exact receipts.
