**V1 update (2026-09-29 owner-local):** The owner selected a shared,
Apache-licensed pretrained base for Fable V1. The fresh-initialization-only
rule below remains the long-term first-party foundation destination, but is
superseded for V1 by
[`MFM_V1_LICENSED_BASE_DIRECTION_2026-09-30.md`](MFM_V1_LICENSED_BASE_DIRECTION_2026-09-30.md).
The older Gemma instruction-tuned trainer is still research-only. No V1

## Decision

Fable's core Memory Formation Model (MFM) must use first-party weights with a
documented fresh-initialization lineage. The Fable Builder Model (FBM) must not
download, call, fine-tune, merge, or ship Gemma or any other third-party
pretrained weights as the core MFM or as its hidden runtime dependency. A
self-contained export of fine-tuned Gemma weights remains Gemma-derived. A
local copy, a full-weight update, and an adapter merge do not change that
lineage.

The earlier `google/gemma-4-12B-it` text and multimodal training routes were
prepared under a different assumption. They have not trained an MFM. The
Gemma snapshot staging, Magnolia transfer, four-A100 probe, and paid fit in
`MFM_GPU_EXECUTION_HANDOFF_2026-09-29.md` are **superseded execution plans**.
Do not stage that checkpoint or purchase GPU hours for those commands. Keep
their code and receipts, if any, as historical, explicitly unqualified
research artifacts until the native route replaces them. Do not mistake
contract tests or a prospective probe for a model-quality result.

This is a lineage requirement for **both learned core stages**: the general
MFM foundation and its formation specialist. It does not forbid
implementing a published architecture from a configuration with newly
initialized parameters, using open-source model mechanics, consulting
research, or using an owner-authorized frontier model to create clearly
attributed training candidates. As in N0, an assistant teacher may supply
examples, comparisons, explanations and hard negatives for public semantic,
sensory and formation learning. Each case must retain its source, author,
authorization, generator, seed, model/version when available, source-text
references and review status. Teachers do not supply inherited core MFM
parameters, independent evaluation labels or Claim authority. Optional
external feature tools under Fable's controller have a separate contract and
cannot become the required formation path or the owner of personal memory.

## What FBM builds for each person

The lineage has two learned stages. **Stage A** initializes a first-party
public-data foundation from fresh weights and learns broad language,
evidential, temporal, social, code and sensory representations from admitted
public/permissioned data, with separately attributed assistant teaching.
**Stage B** trains a specialized MFM atop that *first-party* checkpoint on
source-linked, longitudinal formation operations. The specialist may add
newly initialized fusion/output parameters and update Stage A weights as
required by capability evidence. Neither stage imports third-party pretrained
weights. They contain neither Elaina's nor Rayan's private life as portable
memory.

Fable can ship a reusable, identity-neutral checkpoint at each first-party
stage. A consumer need not repeat all public pretraining from random weights
when verified first-party weights are supplied; fresh initialization is
required at the root of that checkpoint lineage. FBM must recommend suitable
rights-cleared public base packs and let the user select or add public packs
for the particular build. It must inventory sources, license and distribution
rights, modalities, language, scope, duplicates and exact revisions; test
whether the selected pack combination is adequate before training or claiming
capability. Selection is an input to a versioned build, not an excuse to mix
unlicensed, private or low-coverage material into a shared checkpoint. A user
may choose a more extensive first-party rebuild with adequate data and
compute; there is no compulsory outside checkpoint or third-party service.

FBM then constructs and evaluates the instance's evidence-linked memory,
host, relationship, assistant-self and identity roles, and any governed
instance-specific MFM adaptation supported by the person's authorized data.
It cannot copy private instance weights into a shared checkpoint or treat a
generic seed plus a profile prompt as a completed personal entity. A public
pack never becomes evidence that a user lived the events described in it.

FBM's result must pass source and subject separation, correction/deletion,
rollback, changing-state and later-judgment tests. The deterministic memory
gate alone decides canonical writes. A personal-model claim depends on the
observed build and causal behavior of the full entity, not merely on declaring
weights first-party. The owner can authorize a sparse build while its
unsupported personal inferences remain uncertain; FBM must not invent a
history to fill gaps. This MFM remains separate from N0/N1 personality
training. It can share research lessons and architectural ideas without
loading N0 weights or waiting for N0 to finish.

## Preserve the usable work

- Keep `FormationContextPacket`, `MemoryProposalBundle`, registered source
  reads, exact byte anchors, source ancestry, temporal scope and the
  deterministic gate boundary. MFM proposes; source and Claim authority
  stays independent.
- Keep the frozen 49,819-case owner-authorized synthetic mixture and its
  hashes documented in `MFM_CORPUS_SOURCE_RECEIPT_2026-09-29.md`. It is
  **training-only formation supervision**, mostly text and structured data.
  Its generator families and unreviewed targets cannot certify held-out
  generalization or multimodal perception.
- Keep the raw-media source decoding, provenance and loss-masking ideas where
  architecture-independent. The Gemma chat template, tokenizer, Unified
  processor, pinned revision, 12B export threshold and pretrained-weight
  staging receipt are not native model contracts. Rebuild and bind the
  processor, tokenizer and sensory representations for the chosen native
  architecture. Record the provenance of any non-weight component too.
- Keep exact-source training receipts, sharding, bounded full backward probe,
  complete export, resume binding and critical-error reporting as methods.
  New native code, data, processor, hardware and model fingerprints require
  **new** CPU and GPU receipts. Existing Gemma-bound receipts cannot be
  rebadged as native proof.

## Native full-capability build order

1. **Specify the two-stage objective and representation.** Bind
   text/code/structured evidence and original image, audio and video input
   to source, speaker, subject, time, uncertainty, competing interpretations,
   corrections, deletions, patterns and episode boundaries. Choose an
   architecture for a public semantic/sensory foundation followed by
   cross-source fusion and evidence-pointer/structured proposal specialization.
   Stage A starts at fresh initialization; Stage B starts from the verified
   first-party Stage A checkpoint. Audit both load paths against inherited
   outside weights. There is no permanent parameter, context, modality or
   deployment-size ceiling.
2. **Admit the public packs before foundation training.** Native language and
   sensory competence requires data well beyond the 49,819 formation cases.
   Build rights-cleared source packs across text/code, image, audio and video
   with exact revisions, license/distribution rights, lineage, deduplication,
   contamination, tokenization and coverage receipts. Bind separately
   authorized teacher cases and mark their targets as teaching rather than
   independent truth. Keep personal Elaina/Rayan material in authorized
   private custody. Record adequacy by intended language, source family,
   modality, time and generalization behavior. **No foundation-pretraining
   GPU job is authorized merely because a trainer exists; the actual broad
   pack and audit must exist first.**
3. **Train and specialize the first-party lineage.** Train Stage A on those
   audited public packs from fresh weights. Then initialize Stage B only
   from the exact first-party Stage A artifact and train source attribution,
   subject separation, temporal revision, abstention and grounded proposals
   using the preserved 49,819-case formation mixture *as one training tier*
   plus independently sourced broader curricula. A simple `from_config`
   replacement on 49,819 examples would initialize random weights but
   would not create a capable foundation or MFM.
4. **Qualify learning before a full fit or promotion.** Freeze independent
   people, source systems, generators, scenarios and time windows for
   development and a separately custodied FINAL. Test unseen histories,
   language variation, multimodal grounding, long context, source collisions,
   abstention, temporal revision and deletion influence. Compare strong
   baselines on identical opened evidence. Report subject/provenance/false
   memory errors separately. Check whether scale and training data are
   adequate for each claimed capability; grow the architecture and mixture
   when evidence demands it rather than calling an undersized run the
   finished model.
5. **Prepare the new compute route.** CPU-audit every exact training input,
   processor output, full-context budget, initialization, checkpoint and
   storage path. Then measure a real complete forward/backward/optimizer
   step, checkpoint/export and restart on the intended allocation before
   pricing a full run. Use Magnolia, Kaggle or rented GPUs only with the
   appropriate verified data and hardware route. A hardware probe is not a
   formation-quality or Stage G acceptance receipt.
6. **Promote only the governed full loop.** Evaluate native MFM proposals
   through source authentication, deterministic authority, accepted
   projections, retrieval, native personal judgment and observed outcomes.
   Use counterfactual subject-state interventions, correction/deletion,
   replay and downstream-model replacement. FBM must reproduce an
   independently qualified build for another authorized host before a
   consumer-scale construction claim.

The amount of data, computation and independent evaluation required for this
route has **not** been measured. It may be much greater than the prior Gemma
fine-tuning plan. The decision changes what counts as a valid finished MFM;
it does not claim that native full sensory competence is already affordable,
trained or demonstrated. Record this correction as a procedure-only FBM
lineage lesson without private payload or a false successful training label.
