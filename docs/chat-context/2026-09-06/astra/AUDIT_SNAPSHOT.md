## 1. The verdict

**Keep the destination. Change the proof strategy.** ALICE is intended to be a continuing intelligence with an Elaina-derived identity, a distinct understanding of Rayan, its own accumulated experience and the ability to act on durable goals. Reducing it to a generic assistant with retrieved notes would violate the recovered owner decisions. [C01] [C02] [C04] [H06]

The strongest work so far is architectural: provenance, source/host/self separation, explicit authority, replaceable projections, correction, deletion, reproducibility and migration boundaries. These are useful engineering commitments. Several are already supported by released foundations and reference implementations. [C03] [C12] [C13]

The weakest link is the progression from those commitments to measured cognition. The latest located work remains in public-judge qualification for synthetic personality candidates. That is upstream of candidate screening, acceptance, training and integrated memory qualification. More qualification machinery does not itself close that gap. [C16] [C18]

My highest-priority change is a requirement-to-experiment ledger: each important promise should point to a runnable test, a baseline, a result and a remaining failure. This should replace repeated reinterpretation of the objective.

## 7. Memory architecture: the design to preserve

The v4.1 architecture is fundamentally a governed memory system with learned interpretation and derived views. A collection of database names is not its defining feature. [C03] [C04]


**The logical flow:** experiences and source artifacts enter an evidence fabric. Learned formation proposes typed claims and relationships. Authority and policy checks admit eligible state. Graphs, vectors, episodes and person models provide different retrieval and reasoning views. The executive uses them to act; outcomes return as new evidence.

The Experience/Event Fabric preserves what happened and how it was observed. The Claim Fabric preserves what the system currently accepts and how that acceptance changed over valid time and recorded time. The distinction supports both "what was true then?" and "what did ALICE believe then?"

Graph and vector stores are derived access paths. Episodes organize experience. Host, relationship and self models summarize governed evidence. Mission state tracks operational commitments. Workflow engines make execution durable. None should acquire accidental authority merely because a model retrieved a record from it.

The archive holds source material and artifacts under retention policy. The training registry tracks datasets, checkpoints, descendants and evaluations. It is essential because changing a source can affect more than a database row.

This division is technically defensible. Hindsight and Zep also separate important memory roles and temporal structure, so it is not novel simply to have multiple memory planes. ALICE's task is to make the full semantics work reliably for its identity and mission requirements. [R01] [R02]

## 8. Memory architecture: what needs correction or proof

| Design issue | Audit judgment and required evidence |
|---|---|
| One authority per namespace and generation | Preserve. Derived stores must declare which authority generation and watermark they reflect. Test stale views during correction and recovery. |
| Learned formation plus deterministic gate | Preserve the split. The gate can enforce schema, provenance, permissions and declared constraints. It cannot generally prove that a natural-language interpretation is semantically true. |
| Bitemporal claims | Preserve. A correction arriving today about an old event must not erase the historical record of what ALICE believed yesterday. |
| Causal graphs | Useful hypothesis representation. An edge labeled causal is not proof of causation. Store observations, explanations and intervention evidence separately. |
| Episodes and summaries | Useful compression with source links. Measure what gets lost, especially exceptions, rejected plans and mixed outcomes. |
| Raw capture and consolidation | Broad capture supports future learning. Permanent retention should follow utility, custody and deletion policy. Avoid an indefinitely growing transcript dump. |
| Model-independent memory | Valid architectural aim. Behavioral identity migration requires retraining, distillation or adaptation where needed; adapters are not automatically portable across backbones. |
| Deletion | Trace through indexes, summaries, caches, datasets and checkpoints. A deleted row does not prove that a trained model has forgotten it. |
| Multi-store deployment | Logical separation does not require one distributed service for every logical role from day one. Co-location can retain the full contracts and replacement interfaces. |

These are mostly implementation and evaluation obligations already implicit in the design, not reasons to discard it. [C03] [C04] [C20]

The largest missing architectural measurement is the **semantic conservation test**: after ingestion, formation, adjudication, projection, retrieval, context assembly and response generation, do the original distinctions still survive? A perfectly replayable ledger can preserve a mistaken extraction perfectly. Storage correctness and semantic correctness must be measured separately and together.

For deletion-influenced weights, the existing owner ratification already permits stronger remedies such as clean retraining or retiring an affected artifact when residual influence is unacceptable. Preserve that honesty. Do not promise universal precise unlearning from a successful database rebuild. [C20]

## 12. Public-judge qualification needs a scientific boundary

The v1.8.3 scoring change has a defensible explanation: a correct reject decision can differ from an internal six-field explanation without being semantically wrong. Fixing that mismatch is legitimate. It is still a scoring change made after observing Gemma's results. The same public 16 tasks have also driven prompt and runtime diagnosis. [C17] [H09]

**Those tasks now function as a calibration/development suite.** Passing them can establish conformance to the chosen public contract. It should not be reported as an unbiased estimate of general judge accuracy on unseen personality-completion decisions.

The required separation is:

- Public calibration: debug schemas, runtime behavior, source/target wording and the meaning of the rubric.
- Prospective qualification: freeze the effective policy before evaluating fresh, independently labeled cases with the needed error categories.
- Candidate adjudication: evaluate the frozen candidate pool with qualified, version-bound judges and explicit disagreement handling.
- Final certification: use an independent evaluator and protected evidence at the already authorized boundary.

Keep MC8 sealed. A separate prospective public or non-MC8 qualification set can address judge calibration without exposing the final test. Its cases should cover the failures that matter: source-history fabrication, actor substitution, invented commitments, unsupported generalization, legitimate adjacent synthesis and appropriate uncertainty.

Do not collapse technical failure into a semantic HOLD or UNKNOWN. Empty output, malformed JSON and transport failure measure availability or runtime conformance. They are not evidence of calibrated uncertainty.

Static inspection also found that legacy secondary-field thresholds remain in the policy payload while the ratified decision worker applies the newer decision-centric rule. The controller carries a separate amendment receipt. This is not, by itself, a proven execution bug. It is an avoidable inspection hazard. Produce one machine-readable effective policy and test that the worker and receipt agree with it.

This recommendation strengthens the existing independent-certification goal. It does not invalidate preserved rows or authorize another expensive rerun merely for appearance.

## 13. Synthetic completion is necessary; synthetic certainty is not

The project explicitly intends ambitious synthetic expansion, potentially millions of controlled situations. That is compatible with rigorous science. The error would be treating generated volume, internal consistency or agreement among related models as new independent evidence of what Elaina actually did or would certainly do. [H03] [H06]

E0 remains owner-attested source evidence. E-INF is grounded inference. A-SYN is controlled completion. These can all be useful training inputs while retaining different epistemic status. Simulated experiences must not become ALICE's lived autobiography.

The source-family registry is a major strength. Multiple descriptions of the same event, artifact or relationship episode should remain together across splits. A synthetic descendant contributes no additional E0 family. All substantive source passages remain canon; grouping them for leakage control does not demote them. [H06, pp334-340; pp385-395]

The original hardening policy calls for one-sided 95% upper false-promotion bounds of 2%, 1% and 0.5% across tiers. That requires a defined population and unit of error. Is the risk over completion decisions, evidence families, behavioral situations or future actions? The recovered material does not establish a satisfactory operational answer.

For illustration, with independent Bernoulli trials and zero observed errors, the upper bound is 1 - 0.05^(1/n). Meeting those three bounds requires at least 149, 299 and 598 independent trials respectively. This is a calculation, not a claim that one E0 family equals one trial. Nor do three paraphrases of one case automatically count as three independent trials.

Fresh independently labeled completion decisions can add evidence. Real longitudinal observations can add evidence. A larger synthetic training set can improve the model. None of these possibilities justifies inflating the effective certification sample size.

The correct response to limited confidence is a productive research loop: identify the uncertainty, generate falsifiable alternatives, seek distinguishing evidence, run controlled learning and reopen the decision. Permanent abstention is not the intended end state.

## 14. A training program that preserves the purpose

The next training design should compare meaningful alternatives under a frozen evaluation contract. It should not choose a backbone or corpus size because a previous script happened to support it.

**Data and evaluation preparation**

1. Preserve the full owner-attested canon. Build a versioned source-family map and hold out families or decisions before generating descendants.
2. Separate biography recall, semantic interpretation, personality behavior and general reasoning. A gain in one can conceal a loss in another.
3. Include ordinary situations, relationship-specific behavior, conflict, low-intensity behavior, exceptions and novel combinations. Avoid training only on dramatic or emotionally saturated scenes.
4. Label both unsupported softening and unsupported intensification as fidelity failures. Style resemblance alone should not dominate.
5. Retain negative examples, counterevidence, uncertainty boundaries and original source access.

**Model experiments**

Compare a frozen general model plus governed retrieval, identity prompting plus the same retrieval, and trained identity variants on identical held-out inputs. Train AMFM against independently adjudicated semantic proposal bundles and test it before connecting it to the fabric. Existing model baselines remain useful without being mistaken for ALICE's final cognition. [H06] [C04]

Scale synthesis when the held-out improvement per unit of compute justifies it. Preserve the owner-ratified mixture and lineage rules unless separately amended. The goal is increasing faithful compositional coverage, not hitting a ceremonial row count.

Research on recursive replacement shows a real danger of losing rare information. Accumulating original and generated data avoids collapse in some studied settings. Together, these findings support preserving real evidence and measuring tail behavior; they establish neither that all synthesis is harmful nor that ALICE's current ratios are optimal. [R13] [R14]

**Promotion evidence:** report fidelity by condition, biography/provenance errors, calibration, generic capability retention, host/source separation and behavior after later learning. Require a candidate to improve the intended capability without quietly changing protected identity behavior.

This keeps the ambitious completion program intact while making its success observable.

## 15. Recollection and LifeSim should test continuing intelligence

G+ should learn from competing systems and recent benchmarks, but a memory benchmark alone is too narrow for ALICE. A useful answer can require a rejected option, an old causal explanation, a current constraint, an unresolved commitment and a new outcome. [H02] [R05] [R09] [R10]

**A proposed retrieval policy:** begin with mission state and the question's temporal/epistemic requirements; retrieve across appropriate planes; check source authority and freshness; inspect original evidence when summaries disagree or stakes justify the cost; assemble a bounded context with explicit missing evidence. This is an empirical candidate, not a newly ratified destination.

Measure retrieval recall and precision, but also contradiction resolution, stale-belief use, correct abstention, premise detection, answer utility and cost. Include long-context and simple retrieval baselines. Complex memory should earn its latency and maintenance burden.

LifeSim should be a stateful environment, not just a large file of generated life events. The system should experience interrupted work, mistaken predictions, changed goals, duplicate evidence, corrections, missing results, conflicting permissions and restoration from old backups.

| Measurement | Why it matters |
|---|---|
| Learning gain over a reset/frozen baseline | Separates learning from the base model's prior ability |
| Repeated mistake rate | Tests whether outcomes actually change future behavior |
| Mission resumption and duplicate-action rate | Tests durable agency through interruptions |
| False current-belief rate after correction | Tests temporal authority through all memory planes |
| Appropriate generalization to a new situation | Tests learned structure rather than memorized wording |
| Source/host/self contamination | Tests identity and reality boundaries |
| Cost, latency and human attention per successful outcome | Tests feasibility rather than best-case accuracy alone |

Run matched streams and counterfactual variants. If two systems see different information or have different token budgets, report that rather than calling the result a clean architecture comparison.

The important frontier is useful experience-dependent improvement. A million correctly stored events is an infrastructure result until that improvement is demonstrated.

## 16. The Stage G backend gate is too broad as written

The current matrix makes every named candidate mandatory unless Rayan amends it. It also requires individual qualification, same-role all-pairs comparison, meaningful cross-role substitutions, multi-plane combinations, full runs and stress testing. This is an owner-ratified obligation; it cannot be silently skipped. [C05]

The problem is the unit of comparison. The inventory mixes databases, vector services, ANN algorithms, libraries, distributed training facilities and deployment schedulers. These do not all represent interchangeable choices. A comparison of a database service with an ANN index is not meaningful until the shared logical role and surrounding implementation are defined.

The combination requirement can expand faster than the evidence it produces. It risks postponing the core question: does learned memory cognition work in a complete system with the required semantics?

**Concrete amendment proposal for owner review**

| Keep | Change |
|---|---|
| Full logical memory architecture and Mission Graph semantics | Qualify a declared deployment profile and complete selected stack first |

## 20. Novelty: where a defensible contribution could exist

**The broad idea is not novel enough to claim category invention.** Persistent memory, personal models, temporal graphs, reflection, autonomous work and even identity across model replacement all have identifiable prior art. Hindsight is close on epistemic memory roles. HEBB is close on person models and outcome-informed judgment. Memory as Ontology explicitly discusses cross-model identity, although its validation is limited. [R01] [R17] [V07]

A distinctive product philosophy can still matter. ALICE aims at an intelligence that understands its host while remaining a separate continuing entity. That choice affects interface, trust, disagreement and learning. It does not by itself establish a research breakthrough.

| Candidate contribution | Evidence needed before claiming it |
|---|---|
| Source-faithful identity that survives reasoning-model replacement | Controlled behavioral migration study across several model families, with baselines and predeclared failure criteria |
| Governed personality completion from sparse evidence | Source-family-held-out generalization, calibrated uncertainty and a measurable advantage over prompting/retrieval |
| Joint memory and decision-history learning | Stateful experiments showing improved future decisions because outcomes revised specific beliefs |
| Learned formation with correction/deletion guarantees | Semantic and storage correctness through all projections and training lineage |
| Complete Mission Graph with continuing personal context | Real tasks demonstrating resumption, reduced repeated context and fewer recurrent mistakes |

A useful research claim would be bounded: "Under these tasks and budgets, this method improves specified fidelity and continuity measures over these baselines." A claim such as "one AI that truly knows your whole life" is a destination, not a scientific result.

For a company, novelty need not mean a wholly new neural architecture. Product execution, reliability, distribution and a difficult-to-reproduce learning/evaluation process can create value. If host data stays private, the moat should not assume unrestricted central accumulation of everyone's personal history.

**My judgment:** ALICE has a promising synthesis and research agenda. Its distinctiveness must now be earned through experiments and user outcomes.

## 22. Research to use: identity, weights and self-improvement

Behavioral simulation research on 1,052 people is relevant to personality modeling, but its reported similarity is normalized to people's own test-retest consistency on particular instruments. It does not mean a model reconstructs 85% of a whole person. ALICE needs situation-specific fidelity and uncertainty measures. [R12]

Persona vectors and the Assistant Axis offer ways to study character changes inside tested open models. They support measuring drift during training and long conversations. Their generic assistant-stabilization objective should not silently become ALICE's personality target. A custom identity must preserve its own authorized behavioral distinctions while remaining truthful about source and self. These methods are exploratory diagnostics, not proof of a stable reconstructed person. [R19] [R20]

The July 2026 sequential weight-write study found substantial interference when teaching invented facts to Qwen3 models. Diverse training helped usable knowledge, while later writes still disrupted access to earlier facts. Context remained a strong recovery channel in those experiments. This supports ALICE's distinction between learning how to behave in weights and preserving revisable personal facts in governed memory. It does not prove lifelong neural learning impossible. [R18]

Nested Learning and its Hope proof of concept motivate different update timescales and richer memory/optimization mechanisms. Keep them as controlled research candidates. They are not a drop-in solution for faithful autobiographical memory, exact deletion or consumer-grade continual learning. [R21]

Preference Leakage shows why related generators and judges can share biases. Different model names are not enough to establish independent certification. Use blinded origin information, family-aware analysis, independent labels and held-out evidence. [R15]

Agent-scaling research reports task-dependent benefits and failures. Use a coherent executive with scoped specialists. Compare multi-agent orchestration against a single strong executor at matched cost; do not require debate on every turn. [R16]

Darwin Godel Machine and AlphaEvolve show productive loops of proposing changes, evaluating them and retaining useful variants. Borrow evaluator isolation, archives and measured promotion for skills, code and scientific work. Their success in bounded coding or algorithm tasks does not establish unrestricted general self-improvement. [R22] [R23]

## 23. Seven experiments that would change the assessment

These are proposed experiments, not new ratified release gates. Each resolves a concrete uncertainty.

| Experiment | Comparison and decisive result |
|---|---|
| 1. Identity fidelity | Same base/retrieval with prompting versus trained identity variants. Held-out situations must show improved interpretation and judgment without biography fabrication, generic softening or exaggerated intensity. |
| 2. AMFM formation | Trained AMFM versus a general-model baseline on identical proposal-bundle tasks. Score entities, temporality, contradiction, source status and correct routing eligibility separately. |
| 3. End-to-end semantic conservation | Feed both gold and learned proposals through the same complete fabric. Separate model mistakes from storage/projection/retrieval mistakes. |
| 4. Stateful mission learning | Matched streams with persistent learning versus reset/frozen baselines. Measure later success, repeated mistakes, interruption recovery and unnecessary user effort. |
| 5. Retrieval ablation | Simple retrieval, long context and selected structured strategies under disclosed budgets. Require actual answer/decision benefit, not only retrieval-score improvement. |
| 6. Identity migration | Replace a reasoning substrate. Test preserved commitments, values, source attribution, behavioral fidelity and calibrated changes. Account for adapter migration work. |
| 7. Correction and deletion propagation | Correct or revoke influential evidence, then restart, rebuild and restore. Test stale derivatives and affected training artifacts as well as database contents. |

A convincing early evidence package could contain a small trained AMFM, a measured identity candidate, one complete stateful memory scenario and a clear comparison against simpler baselines. It would be more informative than adding another large list of supported technologies.

Freeze metrics and decision criteria before evaluating the fresh test. Keep developmental experiments separate from final certification. Use source-family-aware splits and disclose model, quantization, prompts, context budgets, hardware, costs and failures.

Do not pick the next experiment solely because it fits existing automation. Choose the experiment whose result would most change the architecture or training decision. ## 26. A first business case consistent with ALICE

**Candidate initial user:** a researcher or technical builder managing several long-running projects. The recurring pain is reconstructing why a decision was made, what failed, what remains blocked and what should happen next. This segment fits the comic and Mission Graph, but it remains a hypothesis until interviews support it.

The product benefit should be concrete: resume important work with the right context, avoid repeating rejected decisions and carry a mission through interruptions. Personal intelligence is the mechanism and long-term destination.

**Proposed discovery program**

- Interview 10-20 tightly matched users about a recent real project interruption. Ask them to show their current artifacts and workaround.
- Identify the same recurring failure across several users. Record frequency, consequence and the effort they already spend solving it.
- Recruit a small design-partner group around that one workflow.
- Use product specifications and interaction prototypes while G/G+ continues. Clearly label prototypes.
- After the required engineering gates, observe repeated usage on real work. Measure useful completed missions, return usage, corrected mistakes, intervention burden and willingness to pay.

The 10-20 interview range already appears in the company plan. These numbers are a practical discovery proposal, not YC admission requirements. [C10]

The initial demo should show a mission across two sessions, an interrupted task, a corrected belief, a retrieved rejected option and a verified resumed action. Show the evidence behind the behavior. A staged model swap can illustrate the architecture only if the behavior is tested; a successful import alone is weak proof.

Unit economics must include local hardware burden, onboarding, storage, support, background work and optional remote inference. Local execution can change who pays for compute; it does not make the cost disappear. A larger-model ensemble must justify latency, memory and energy with measurable benefit.

The full Mission Graph can underpin this narrow workflow. A general lifelong operating system is the expansion story. It need not be the first thing every customer is asked to understand.
