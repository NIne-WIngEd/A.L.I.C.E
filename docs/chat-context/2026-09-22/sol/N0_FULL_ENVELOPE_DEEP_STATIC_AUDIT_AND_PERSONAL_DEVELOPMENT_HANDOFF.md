## Deep source audit is still open

The prior Sol was explicitly continuing source-level falsification after green CI. The current chat must continue that work rather than jumping to Magnolia.

Areas still requiring source-level scrutiny include:

1. **Endpoint-role supervision.** The current behavioral endpoint loss consumes executor source/target support aggregates. We still need to prove that this objective causally trains/tests the actual role-conditioned endpoint/readout semantics rather than a support-selection proxy. Historical endpoint-role failures make this high priority.

2. **Global versus step-conditioned factor semantics.** Relation semantic state, direction, and modifiers have step-conditioned paths. Role/traversal/control ownership across multi-step programs must be checked for any remaining whole-program shortcut that breaks valid compositions.

3. **Behavioral curriculum shortcut resistance.** TRAIN/DEV entity and query-template separation exists, but generated scenario families, scalar metadata, answer construction, reliability/recency/provenance patterns, and deterministic labels must be audited for shortcuts that can satisfy DEV without learning the intended semantics.

4. **Causal behavioral tests versus shape tests.** A test that proves geometry, nonzero gradient, a parameter-report flag, or permutation wiring does not by itself prove the claimed behavior. Every critical claim should be traced to an independent intervention where possible.

5. **Additional runtime views.** Arbitrary extra views are supported, but future personal-state views must not turn precomputed vectors, availability, reliability, or descriptor geometry into a label leak or hidden identity axis.

6. **Fusion/latent/public-judgment causal chain.** Continue checking that relevance, decisive evidence, irrelevant evidence, recoverability, noncollapse, and candidate judgment are causally connected in the intended direction rather than merely jointly differentiable.

7. **CPU qualifier fidelity.** Before external execution, verify from source that the CPU fixture is neither easier nor structurally different from the governed training topology and does not prove behavior by reading report booleans.

8. **Final-validation independence.** Keep final-v2 sealed. Training/DEV construction must not derive targets, templates, thresholds, or repair choices from final outcomes.

These are audit questions, not authorization for speculative fixes. A concern becomes a code change only after its causal defect is established.
