# N0 full-J3 distributed route review after job 576213

Status: **design and qualification requirements, not an implemented training route or a P43 PASS.** The scientific source remains `a19f8e8893422702c138182f239064385addf91c`. This review is based on its actual trainer, joint-step, objective and stage-policy code, the failed two-rank gradient experiment and preserved rank receipts. The failure record is `N0_P43_J3_DDP_JOINT_STEP_FAILURE_576213.md`.

## What failed and what it does not establish

The original trainer wraps `N0FullEnvelopeTrainableSystemV1` in DDP with `find_unused_parameters=True`. `execute_full_envelope_joint_step` calls that same wrapper eight times in J3: MLM, teacher, semantic operator, full fabric primary and three counterfactuals, and natural relation. The objective combines these outputs outside any one DDP forward and calls backward once. Job 576213 executed this exact arrangement with 17 verified nonreentrant checkpoint modules on each rank. Both ranks failed on the first real J3 backward with parameter 385 (`stack.public_judgment_probe.score.2.weight`) marked ready twice. PyTorch's [upstream multi-forward/one-backward issue](https://github.com/pytorch/pytorch/issues/60844) matches the mechanism; the N0 explanation is still a source-based inference, pending a successful alternative on the same inputs. The failure was not OOM. Its memory samples stop at the exception, before completion and before AdamW state allocation. Buying VRAM alone cannot establish correctness for this route.

## Candidate boundary and interface

Place **one DDP boundary around the complete joint objective**, with the original system and `FullEnvelopeJointTrainingObjectiveV1` registered as children. The outer `forward` executes `execute_full_envelope_joint_step(system=self.system, objective=self.objective, ...)` exactly once; the inner calls use the unwrapped child and keep all active macro families, replay, natural-relation and four full-fabric views. Return **only the scalar joint loss through DDP**. Retain small detached family-loss statistics and plain metadata for the trainer's post-backward effective-batch EMA. Returning the full diagnostic result as DDP output would expose tensors not used by the loss to `find_unused_parameters` and could recreate a reducer mismatch. Avoid retaining any live graph on the module between microbatches. `update_ema=False` inside forward and once-per-effective-batch global observation outside remain precommitted.

This is a proposal, **not a claim that DDP will accept all stage-specific graphs**. Do not replace the eight tasks with separate backward/optimizer steps, remove counterfactuals, detach outputs used by the loss, set `find_unused_parameters=False` globally, or set `static_graph=True` on evidence from one J3 shape. A scalar-only DDP output, changing unused and frozen parameters across J1/J2/J3, and checkpointed shared backbone all need actual distributed tests.

`FullEnvelopeJointTrainingObjectiveV1` contains the balancer state and is currently saved separately; registering it inside the outer module changes the prepared model's accelerator-state names. Naively saving `unwrap_model(outer).state_dict()` under `full_system.safetensors` would introduce `system.`/`objective.` prefixes and break consumers. Similarly, directly calling the outer `.system` for some trainable lanes would bypass the intended DDP boundary. Both are explicit review blockers.

## Qualification order and rejection conditions

1. Build a versioned, isolated candidate; keep pinned source, original receipts and failed evidence roots intact. Compile and inspect source-bound inputs. Treat syntax/static checks as preliminary only.
2. On reproducible public or synthetic fixtures, compare **original unwrapped** and candidate whole-step loss, all active raw family losses, and named per-parameter gradients for J1/J2/J3. Include changing candidate/field/edge/view cardinality, long additional-view source, frozen and unused heads and four J3 counterfactuals. Compare optimizer group identities, effective-batch sample weights and EMA. Fail on silent zero/None gradient drift, parameter omissions or output loss drift.
3. With two CPU Gloo ranks, exercise multiple consecutive dynamic batches and all stage graphs, accumulation and `no_sync`. Check each rank's gradient against a reference built from its local batches with the same reduction and AMP-independent tolerance. Exercise checkpointed and noncheckpointed modes where supported; record which one matches the registered trainer. A single toy forward success is insufficient.
4. On two real GPUs, repeat with pinned public mixtures and trainer checkpointing: all 18 J3 case pairs with completed backward, complete gradient evidence, parameter nonmutation in a backward-only probe, per-rank allocated/reserved/driver peak and exact 85% capacity check. If any case fails, retain the first failure and all rank receipts. Do not infer AdamW fit from a backward-only result.
5. Separately measure optimizer creation, first and later AdamW steps, mixed-precision scaler, full accumulation and checkpoint save/load on the same route. Verify checksum-bound restart vs uninterrupted controls, stage transitions and all authority dependencies. Only then can a successor P43 gate, training authorizer and trainer hash/lineage be updated together and rerun on a fresh source revision. If measured VRAM fails, choose an evidence-backed state/activation strategy or buy verified high-memory hardware; keep all science and gates intact.

The current FBM seed should encode the failure classification, design constraints, source lineage and explicitly unknown completed-backward/optimizer peak as **procedure only**. It cannot label a personality-model outcome, successful training, or a P43 capacity PASS.
