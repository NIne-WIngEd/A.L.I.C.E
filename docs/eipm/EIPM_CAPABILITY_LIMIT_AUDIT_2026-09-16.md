# A.L.I.C.E. EIPM Capability-Limit Audit — 2026-09-16

**Status:** owner-directed architecture audit / current interpretation authority  
**Scope:** personality-model lineage from project doctrine and private-substrate generation through curated EIPM data and the current N0 fusion stage  
**Purpose:** distinguish validation and finite execution controls from accidental permanent capability limits

## 1. North star

A.L.I.C.E.'s personality system is not a generic assistant persona layer. The target remains the highest-fidelity achievable reconstruction of Elaina's identity/judgment patterns that the source evidence can support, with clone/reconstruction transparency, explicit uncertainty, provenance, and later governed Alice continuity.

The personality model is the durable identity/judgment core. It does not need to duplicate the replaceable world model, tool planner, memory database, or prose generator. That separation is architectural specialization, not a reduction of identity fidelity. The identity core must nevertheless expose enough semantic, structured, relational, conceptual, interpersonal, affective, provenance, uncertainty, and evidence state that the surrounding reasoning/generation fabric can behave as A.L.I.C.E. rather than as a generic assistant wearing a style prompt.

The comics and governing documents require behavior richer than trait imitation: contextual judgment, disagreement, initiative, relationship sensitivity, uncertainty, self-reflection, values, tactical reasoning, changing stance by context, and transparent reconstruction status. No implementation shortcut may collapse that target into a generic personality score, a closed trait taxonomy, one pooled vector, or a static prompt.

## 2. Governing interpretation rule

**Validation is not limitation.**

A validation rule may reject corrupt provenance, unsupported authority, malformed tensors, unknown checkpoint vocabulary ids, leaked evaluation data, invalid lineage, or an implementation that fails a capability contract.

A temporary execution control may bound one run's steps, batch size, wall clock, GPU allocation, current context window, checkpoint save interval, curriculum tranche, or serving budget.

Neither category becomes a permanent A.L.I.C.E. capability limit.

If a current checkpoint tensor shape, vocabulary, context window, ontology, graph shape, view count, or compute route is insufficient for measured fidelity/capability, the required action is migration, expansion, continuation training, architecture scaling, or architecture replacement. The project must not reinterpret the old number as an invariant merely because it already exists.

## 4. Private substrate generation audit

### 4.1 E0 / E-INF / A-SYN authority separation — PASS

- E0 remains immutable historical evidence.
- E-INF remains revisable evidence-derived inference.
- A-SYN remains synthetic behavioral completion, never historical truth.
- later A-EXP/A-SELF remain separate from historical source authority.

This is governance required for fidelity, not a capability restriction.

### 4.2 UNKNOWN versus runtime behavior — PASS

UNKNOWN is correctly treated as an epistemic label rather than a forced runtime blank. A-SYN can provide a practical starting prior without rewriting history.

### 4.3 Coverage expansion — PASS

The mature saturation protocol explicitly removed hard row ceilings and made expansion coverage-driven. Post-curation targeted regeneration remains available when curation or later measurements expose holes.

Historical Wave 1 proposal counts were batching/planning controls only. They are now explicitly documented as non-ceilings.

### 4.4 Coverage taxonomy — PASS WITH OPEN-ONTOLOGY RULE

Coverage cells are search/audit instruments, not the definition of a human personality. The taxonomy must expand whenever source evidence or measured behavior reveals a missing dimension or interaction.

### 4.5 Evidence-packet minimization — CORRECTED

Older wording requested the "smallest relevant evidence packet." This could be misread as a context cap. Current authority is **smallest sufficient evidence packet**: omit irrelevant bulk, but expand context whenever cross-source history, relationship state, temporal state, contradiction, wording nuance, or another dependency could change the judgment.

### 4.6 Alternative branches / hard negatives — CORRECTED

Older documents allowed a broad reading in which plausible rejected branches could become hard negatives. That can destroy genuine human plurality.

Current rule: **not selected is not false**. Plausible alternatives remain competing/co-valid hypotheses where evidence permits. Hard negatives require actual contradiction, incompatibility, provenance invalidity, or another grounded reason that the branch is wrong for the supervised judgment.

### 4.7 Corpus freeze — PASS WITH SNAPSHOT INTERPRETATION

A corpus freeze is a reviewable lineage snapshot before gradient, not a permanent closure of personality space. Governed targeted expansion remains available whenever fidelity evidence later exposes a gap.

## 6. N0 semantic substrate audit

### 6.1 Parameter count — PASS

The ratified 136,594,435 semantic parameters describe the current checkpoint. The frontier plan already supersedes older parameter envelopes and states that there is no ratified permanent parameter ceiling.

### 6.2 Architecture family — PASS

The native bidirectional encoder is justified for the specialist semantic/judgment role. It is not protected from replacement: materially better architecture is allowed whenever fixed capability evidence justifies migration.

### 6.3 Token-level representations — CORRECTED

The semantic model previously exposed mean-pooled `encode()` as its primary helper. Although token states existed in the backbone, that API could encourage downstream collapse.

Current code exposes `encode_tokens()` and `encode_views()` explicitly. Mean pooling remains a compatibility readout, not a capability bottleneck.

### 6.4 Context length — CURRENT CHECKPOINT SHAPE, NOT LIMIT

The current semantic checkpoint's 4K training / 8K configured positional window is a checkpoint operating shape. If personality-relevant evidence requires longer native context, use position/context extension or successor training rather than truncating evidence to protect 8K.

Runtime should still prefer retrieval and relevant-context selection for efficiency, but retrieval may not discard necessary evidence.

### 6.5 Public competency registry — OPEN

The current 51 public competencies are a coverage seed/measurement set, not a complete definition of semantic or social competence. Failure-driven additions remain open.

### 6.6 Corpus mixture share controls — TRAINING CONTROL

Any source-token share ceiling exists to prevent one public source from dominating a training tranche. It may be changed when data quality/capability evidence justifies a different mixture. It is not a product-content limit.

## 7. Structured-state audit

### 7.1 Field count — CORRECTED

The historical `max_fields=64` value is retained for checkpoint/config lineage but is no longer enforced as a runtime rejection ceiling. The encoder accepts larger field sets subject only to actual compute/memory availability.

### 7.2 Typed vocabularies — MIGRATABLE CHECKPOINT VOCABULARIES

Field type, provenance class, relation-role, and temporal-scope embedding counts are finite checkpoint tensor shapes. They are not ontology ceilings. New semantic categories require explicit vocabulary expansion/migration and training; they must never be silently aliased to an existing id.

### 7.3 Parameter count — PASS

1,656,064 is the ratified checkpoint size, not a successor architecture limit.

## 8. Evidence adapter / graph audit

### 8.1 Field/node/edge count — CORRECTED

Historical 64-field / 256-edge values are retained as operating-shape hints only. Runtime rejection ceilings were removed. Larger neighborhoods are allowed when evidence retrieval or task fidelity requires them.

### 8.2 Relation vocabulary — MIGRATABLE CHECKPOINT VOCABULARY

The current public relation names and embedding table are a seed vocabulary for the ratified checkpoint, not the final persona/evidence ontology. New relation semantics require explicit registry/checkpoint expansion. Unknown relations should fail closed until migrated rather than be semantically aliased.

### 8.3 Relation reasoning — PASS FOR CURRENT PUBLIC GATE

The repaired dual-endpoint graph passed the untouched relation-essential challenge at the selected step80 while retaining ordinary evidence capability. This validates current public relation mechanics; it does not close future relation families or graph depth/capacity.

## 9. Cross-context fusion audit

### 9.1 Architecture — CORRECTED BEFORE GRADIENT

The earlier concatenate-and-encode fusion draft was superseded before any fusion gradient. The active family is full-scale gated multi-stream self-refinement plus bidirectional cross-attention.

### 9.2 View count — CORRECTED / EXTENSIBLE

N0 currently instantiates three public views: raw semantic, typed structured, and relation/evidence. Three is not a permanent architecture ceiling.

The fusion implementation now supports an arbitrary checkpoint-instantiated view count through `forward_views()`. Later explicit identity-concept and governed residual-concept streams can be added by checkpoint migration without replacing the fusion family.

### 9.3 Parent preservation — CORRECTED

Fusion token residual scales now initialize to zero so ratified parent token representations are exact at initialization. Fusion learns residual changes rather than perturbing parent views before receiving gradient.

### 9.4 Missing-view supervision — CORRECTED

The routing objective now rejects training targets that assign positive mass to unavailable views. It no longer silently masks invalid supervision and renormalizes it.

### 9.5 Curriculum size — TRAINING TRANCHE, NOT CAP

The current 320-row public synthetic fusion curriculum is the first governed optimization tranche for the full-scale architecture. It is not a statement that fusion is complete after 320 rows. Failure-driven expansion remains open.

## 10. Future concept and latent architecture guardrails

### 10.1 Explicit identity concept bank — OPEN, NOT FIXED

The current 2,830 concept entries are a source-derived snapshot. The explicit bank must grow, split, merge, or otherwise migrate when evidence requires it. It must not be replaced by a generic psychology taxonomy.

### 10.2 Residual concept bank — GOVERNED, NOT NUMERICALLY BOUNDED

Older roadmap wording calls this a "bounded residual concept bank." The authoritative interpretation is **governance-bounded**, not count/width bounded: residual concepts may not bypass provenance, explicit-source authority, or auditability. Their number/capacity has no permanent fixed ceiling when fidelity requires additional residual structure.

### 10.3 Adaptive multi-view latent pool — NO FIXED TRAIT SLOT CEILING

The later latent pool must preserve multiple complementary views and may learn/ablate its slot structure. Slot count must not be frozen into a permanent Big-Five-like ontology or one `[CLS]` bottleneck.

### 10.4 Identity Decision Packet — NO SCALAR BOTTLENECK

The final EIPM output remains multi-head/distributional: ranking, stance, values, relationship posture, appraisal, communication posture, grounding risk, provenance/evidence sufficiency, uncertainty, drift risk, and evidence pointers as available. No single scalar reward or personality score may replace this interface.

## 11. Training-stage controls that are not limitations

The following are allowed when explicitly scoped to one optimization/evaluation phase:

- max training steps / epochs;
- checkpoint intervals;
- batch size / gradient accumulation;
- learning rate / warmup;
- one-P100 or two-P100 route choices;
- temporarily frozen parent modules;
- staged/progressive unfreezing;
- finite curriculum tranche sizes;
- held-out challenge freezes;
- current precision mode;
- current sequence/context length;
- temporary latency measurement targets.

Every such control must remain revisable. If capability/fidelity evidence shows the control is suppressing learning, the control changes before the objective is weakened.

## 12. Serving controls that are defaults, not ability ceilings

Efficiency remains important, but defaults such as compact retrieval neighborhoods, cached embeddings, three-candidate common-case routing, or short fast-path context are **serving policies**, not semantic limits.

Runtime must be allowed to expand candidate sets, retrieved evidence, graph neighborhoods, context, deliberation, or compute when the task requires it. Optimize implementation/caching first; do not delete necessary personality evidence merely to hit a preferred latency number.

## 13. External teachers and validators

External teachers/validators may provide development-time competence evidence. They never define identity authority, permanent architecture, or runtime dependency. Skipping redundant external validation is acceptable when A.L.I.C.E. can directly validate the needed capability with governed internal/fixed tests.

Validation rigor should protect scarce compute and fidelity. It must not become MC10D-style infrastructure work that displaces model construction.

## 14. Private-gradient gate

Private N1 identity gradient remains closed until explicit owner authorization. This is a provenance/governance boundary and therefore a valid gate, not a model-capacity limit.

When N1 is authorized, current N0 parent freezing must be treated as an initial stability strategy only. Progressive unfreezing, larger adapters, additional views, architecture expansion, or broader end-to-end adaptation remain allowed whenever identity fidelity requires them.

## 15. Audit conclusion

The project direction from source substrate through the current N0 stage remains aligned with A.L.I.C.E.'s intended personality role. No private personality gradient has been contaminated by the limitations found in this audit because private training has not begun, and fusion has not yet received gradient.

The audit did find implementation/documentation artifacts that could have become accidental limits: 64-field and 256-edge runtime rejection ceilings, an exactly-three-view fusion assertion, a pooled-only semantic helper interface, false-negative wording for plausible alternatives, ambiguous "smallest evidence" wording, and historical row targets that could be misread as corpus ceilings. These have been corrected or explicitly superseded before the next fusion gradient.

**Current rule:** validate provenance and capability aggressively; never turn the current validation shape, compute route, checkpoint shape, taxonomy, dataset size, context window, or optimization schedule into a permanent ceiling on the personality model.
