## Research and transfer limits

The live frontier branch was refreshed to `ce824dd8a4247d4b78f8c1912a0e8c5555f7b47f`. Its October 20 intake remains research, not an architecture directive.

[Experience replay, Section 4](https://arxiv.org/html/1902.10486v4#S4) and its [author implementation](https://github.com/facebookresearch/agem/blob/main/fc_permute_mnist.py) combine current and retained examples in one update. ALICE already retains its valid teaching cases, so the useful distinction is update composition. The paper's small-buffer benchmarks do not prove ALICE retention or prescribe a memory platform.

[Joshi and He's counterfactual-data study](https://aclanthology.org/2022.acl-long.256.pdf) finds that narrow perturbations can neglect other robust features. This supports using the broader training families and complete endpoint objectives, not tuning the two diagnostic families. It does not prove that any particular authored contrast is valid.

[ScopeMem](https://arxiv.org/html/2610.26503v1) reinforces separate repair/harm accounting and preservation of supported correct behavior. Its GUI prefix architecture is not adopted. Distilling every parent output would preserve known mistakes. [PCGrad](https://arxiv.org/abs/2001.06782) requires directional gradient-conflict evidence; aggregate norms and stage losses are insufficient to select it.

## Implementation diagnosis and verification boundaries

The initial public checks exposed a missing rejection for moving an example across unequal group sizes. That rejection was added; the actual 16/24 stratum construction now preserves every example's objective coefficient.

A second check compared two mathematically equivalent accumulation orders as if their FP32 optimizer trajectories were identical. Direct measurement found first-step gradient differences at most `5.96e-8`, with near-zero AdamW bias gradients amplifying a later weight difference to approximately `1.49e-4`. The same native fixture in FP64 reduced gradient differences to `4.44e-16` and state differences to `2.78e-17`. This supports an accumulation-order explanation, consistent with the runtime-version [PyTorch numerical-accuracy documentation](https://docs.pytorch.org/docs/2.7/notes/numerical_accuracy.html) and [AdamW update](https://docs.pytorch.org/docs/2.7/generated/torch.optim.AdamW.html). The learning rule and recipe were unchanged. Verification now combines a direct FP32 gradient comparison with the strict FP64 trajectory test. Original failing outputs remain in the implementation agent's conversation; they are not represented as nonexistent file receipts.

Review also caught an artifact-interface mismatch: the native packet fingerprint requires string keys, while AdamW storage uses integer parameter keys. Exact tensor/container readback preserves those original types and verifies the complete exported experiment. A sparse binary metric now requires observed facts in both contexts before claiming both contexts correct. Public progress contains counts; exact case membership stays in protected plans and events. These are construction/reporting controls, not evidence that private learning improved.
