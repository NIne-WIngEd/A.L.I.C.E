# FBM V1 shared licensed base and personal assembly

**Owner-local direction:** 2026-09-29. **Status:** build contract, not a trained
FBM, MFM, personality successor, or qualified consumer product. For V1, this
supersedes the fresh-initialization-only rule in earlier FBM documents. A
future version aims to replace the shared base with a separately qualified,
scratch-trained first-party base. This does not edit the ongoing N0 branch.

## Shared base and each person's build

Fable V1 may ship a common locally held, Apache-licensed **pretrained**
`google/gemma-4-12B` checkpoint. Pin the upstream revision, every file hash,
tokenizer/processor, license and applicable notices. Keep an immutable source
snapshot and a separately hash-linked working copy. No vendor inference API
may be required for the personal core. Cloning neither changes source lineage
nor removes behavior. The old `google/gemma-4-12B-it` MFM research trainer is
not this production recipe.

FBM must construct each user's distinct learned identity/personality,
Memory Formation, host, relationship and assistant-self components, governed
memory, retrieval and later judgment from authorized evidence. For A.L.I.C.E.,
Elaina's source-person evidence and Rayan's host evidence stay distinct. Keep
each user's newly initialized learned adapters, heads or deltas, source
corpus, optimizer state, indexes, checkpoints and backups in separate private
custody. Never promote private content or gradients to the shared base. A
full-weight fine-tune still has upstream ancestry; a detachable personal
component offers clearer custody but still depends on the base at inference.
At consumer installation, the user supplies corpus access and optional source
choices. FBM must inventory and attribute that data, assemble and qualify the
personal components, and continue governed updates. The user does not have
to hand-label a gold corpus or hire a teacher to build MFM. The prelaunch
shared MFM training and qualification program still needs authenticated
source rights, two independent target reviews and sealed FINAL evidence;
those are development gates, not a labeling job transferred to consumers.
Shared distributable MFM weights require source rights for both
`formation_training` and `model_distribution`. A user's private local
adaptation requires that owner's scoped `formation_training` permission for
weight updates, without a `model_distribution` grant. If local training is
denied, FBM may use separately authorized governed memory/retrieval without
private gradient updates. The existing shared-source admission checker applies
the distribution rule and cannot be reused unchanged for consumer adaptation;
a separate private owner admission contract and tool remain future work.
For MFM specifically, train formation weights under an explicit
source-selection, attribution, uncertainty, consolidation and revision
objective. Connect their structured proposals to registered evidence and the
independent Claim gate. A copied base with a personal-data fine-tune and a
free-form chatbot answer is the obsolete personality Phase 2 pattern, not
this MFM. Compare the trained specialist to a matched seeded-untrained
specialist on the same role clone, plus removal/swaps of the new formation
component. Source-only Gemma output is an optional descriptive diagnostic.

The defensible V1 claim is **a distinct personal learned state and governed
memory under each user's control**, atop a shared licensed foundation. User
rights in original personal artifacts require an explicit Fable agreement.
Do not assert automatic exclusive copyright in AI-generated numeric weights
or sole ownership of the Google-origin portion. Preserve parent hashes,
training authorization and source attribution for every assembly.

## Behavior, privacy and qualification

The base may supply general representations but gets no canonical memory
write authority. Registered evidence and the deterministic Claim gate decide
memory acceptance. Personal identity, judgment and voice must be causally
decisive on independent cross-person, cross-source, long-history and
multimodal tests. Compare the complete entity to a base-only control and
remove or swap personal components. Record each false autobiography,
wrong-subject attribution, unsupported certainty, deletion persistence and
foreign-behavior override. Target zero critical failures on the qualified
suite; no finite suite certifies zero inherited influence everywhere.

Before opening private data, audit and pin the local model/runtime; load safe
tensor files without repository code execution or unsafe pickle. Deny outbound
network egress during private training and inference, disable telemetry and
content logs, and test the boundary. Optional outbound feature models receive
only specifically authorized minimum context. Ordinary third-party cloud
compute sees private data in use unless a separately verified confidential
boundary applies. User-specific weights may memorize intimate evidence and
must receive the same custody, export and deletion treatment. Cloning weights
is not a privacy control and no software stack can prove universal zero leak.
