# Frontier-watch execution guardrail — 2026-09-27

Canonical PR #95 changes how frontier findings are acted on.

A new paper is **not** an automatic reason to change architecture, add a backend,
or launch a qualification program. Judge it against A.L.I.C.E.'s specific
companion objective, current selected stack, maximum capability, scale, hardware,
runtime/latency, privacy, local ownership, and Fable product path.

Classify findings as:

- already covered / corroboration;
- future challenger;
- direct current capability/model/contract improvement;
- architecture-invalidating evidence.

Only the last two justify current work. Infrastructure decisions reopen only on a
concrete observed blocker or strong evidence the selected design cannot express a
needed A.L.I.C.E. capability.

Do not repeat MC10-style overvalidation. A validation program must protect or
change a real next decision. Once that decision is resolved, return to building
memory, judgment, identity, learning and product behavior.
