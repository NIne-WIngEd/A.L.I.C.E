## 1. Memory-Aware Reward Modeling — desired degree of personalization is host/task contingent
**Class:** direct future host-conditioned personal-judgment/recollection evaluation improvement. **Submitted:** October 22, 2026. **Primary:** https://arxiv.org/html/2610.31272

**Method/assumption:** Collect paired memory-conditioned vs unconditioned responses to a participant's requests, privately gathered memory material and explicit human preference labels. Extract rubric features with a fixed evaluator (response quality + memory relevance, proportional personal inference, unwarranted assumptions), train a linear preference predictor and validate by held-out users. Not a fact or authorization adjudicator. **Evidence:** 87 participants, 1,047 judgments including 75 repeated judgments, 821 screened comparisons/673 decisive preferences and stricter 291 pairs for learning. Under ordinary prompting participants preferred memory use on 38.7% vs no-memory 41.9% (19.4% ties); aggressive memory-use prompting does worse. An evaluated reward model favored personalized outputs far more than people. Full feature policy reached 72.8% cross-validated classification vs 67.0% response features only, 62.5% memory features only, and ~58% direct evaluator. Repeat choices are not perfectly consistent, especially weak preferences. **Limitations:** limited people/pairs, constructed response pairs, narrow LLM pipelines; stated preference is not correctness, consent, utility or long-term behavior.

**Already covered:** A.L.I.C.E. has host/relationship state, MRM/Cognitive Recollection, native judgment, scoped source influence, accepted-claim authority and provider output checks. **Actually new:** direct human evidence that *relevant available personal memory can decrease response preference*, and a paired retention/nonuse metric for governed personal expression without equating more personalization to intelligence. **Action:** when native host-specific judgment and candidate selection operate, compare source-grounded memory-use versus non-use in the same task and gather optional user feedback while independently enforcing Claims, privacy, and authorization. Keep profiles subject-scoped and deletion/rollback-aware. **Cost/risk:** paired provider answers, rubric inference and user-feedback collection; optimizing preference alone can reward omission, false memory or overfitting. **Impact:** future; does not change current MFM joint learning.

## 2. ColaBench / MemKB — personalized answers depend on applying external rules to correct host conditions
**Class:** direct future source-native/host-state recollection qualification improvement. **Submitted:** October 22, 2026. **Primary:** https://arxiv.org/html/2610.30989

**Method/assumption:** Construct blind multi-condition tasks from synthetic persona events, private state, and external knowledge documents. MemKB carries a dynamic personal-state summary and direct links between memory records and external source documents; fusion retrieval and agent searches apply current external rules to historically evidenced personal circumstances. **Evidence:** 349 tasks over ten synthetic profiles; MemKB 86.25% full answer accuracy vs Mem0+Hybrid 79.94%, cluster-bootstrap difference +6.30 percentage points [3.19,9.09]; 4.07 vs 4.44 average search interactions. On 111-case ablations, remove state summary -6.31 pp; remove state–document links -10.81 pp. Read Recall alone barely changes, indicating applicability reasoning and connected evidence matter. **Limitations:** constructed histories; LLM-judged answers; external policy correctness/freshness and permission are not established by link existence. Example erroneous inference of a person's opioid use from medication discussion exposes subject/unknown-state risk.

**Already covered:** Experience + bitemporal Claim authority, host vs source-person separation, source-native/live retrieval, cognitive graph and governed query plans. **New:** concrete isolated test of *source-native policy document + host-state premises + exceptions/unknowns* in answer assembly rather than recall-only metrics. **Action:** future one real grounded host-condition→live-rule→source inspection test with unknown premise, current valid times and correction; verify document applicability and never infer host facts from another person's text. No store replacement or extra physical plane. **Cost:** memory–document links, index updates and tool reads; stale links and spurious personal-state summaries are risks. **Impact:** future.

## 3. AMV-Guard — action consequence determines whether the same remembered premise needs reverification
**Class:** direct future Mission action-verification improvement; not a current production defect. **Submitted:** October 22, 2026. **Primary:** https://arxiv.org/html/2610.31446v1

**Method:** Given a candidate action, extract the exact Claim premises it depends upon; calibrate their failure probabilities; encode action-specific consequences and verifier cost/reliability; perform bounded value-of-information checks and either proceed, verify/replan or abstain. Model/prior uncertainty and precondition satisfaction remain distinct. **Evidence:** ToolSandbox Qwen3.5-35B-A3B end-to-end gate comparison, static→adaptive verification cost 1.843→1.219 (-33.9%), safe-proceed recall 100% for both, zero observed *Gate harmful*; Proceed coverage 38.83→44.17%. But **raw end-to-end harm remains 7.03%**, so never claim zero overall harm. Matched action-premise swap chooses high-risk verification vs low-risk proceeding 100% in controlled 500 profiles. Scaling loss alone causes verification rates 0%, 15.8%, 62.8%; calibration/partial verifier failures matter. AppWorld gate-only transfer lowers cost ~21.3% but reduces success/safe recall somewhat and still has ~7.89% Gate harmful. **Limitations:** incomplete extraction can miss critical premises, risk calibration may fail outside simulator, simple verifier observation model, incomplete conjunctions, consequence function requires real specification; many irreversible effects unmodeled.

**Already covered:** host authorization gate, bitemporal Claims, dependency validity (Tether), SAFE-Mem/PerMIT, Mission Graph, provenance. **Actually new:** the decision is not 'is memory true?' but 'does uncertainty justify verification *for this particular action and cost of failure?*' Verified evidence still never grants permission; action authorization independently checked. **Action:** when an action executor exists, contrast low-risk vs consequential action using the exact same historical Claim and permission, include unavailable verifier, stale dependency, abstain, independent outcome. Do not add a new gateway or optimizer before measured need. **Costs:** premise extraction, calibration and verification calls; saved checks can reduce costs, but unsafe missed premises violate correctness. **Impact:** future.

## 4. MHG-Mem — preserve identity occurrences and versioned visual state while reopening original evidence
**Class:** future multimodal Cognitive Multi-Graph/recollection challenger. **Submitted:** October 21, 2026; newly surfaced October 23. **Primary:** https://arxiv.org/html/2610.29995

**Method:** Each observed mention and fact retains its source. Typed occurrence hyperedges group identity-consistent mentions across visual/text sessions; aspect-specific evolution nodes/hyperedges summarize changes; evidential hyperedges lead back to original observations. Adaptive entry-layer graph retrieval and source image inspection answer detail/temporal questions. **Evidence:** 3 runs across MemEye, Mem-Gallery and WorldMemArena-S, using three readers; Qwen3.8-27B LLM-judge average 73.28 vs 63.30 strongest baseline, +9.98 percentage points; Qwen3-VL-8B 57.98 vs 49.78, +8.20 pp. Memory-side ablation fact-only 62.87→with occurrences 68.35→with evolution 71.72→with evidence edges 73.28; retrieval ablation remove agentic search -5.10 pp; remove source inspection -3.44 pp; cross-layer traversal -3.09 pp. **Limitations:** entity merging mistakes, video/person ID ambiguity, model-judge and constructed tasks, visual inference can misattribute an observation; no qualified full-life deletion or governed Claim acceptance.

**Already covered:** required multimodal evidence, episodic temporal, entity/person identity, multi-graph and associative compute, source-native reads, bitemporal Claim authority. **New:** experimentally isolated *separate identity mentions → time-evolving aspect → original image* retrieval structure, especially source inspection's value. **Action:** future one multi-session visual-identity-and-change recollection case with visually confusable objects and corrected identity linking; encode n-ary edges through first-party graph semantics, not a new hypergraph database. Keep host/source-person/self boundaries, source hash, temporal scope, revocation, consent and rollback. **Cost:** VLM caption/entity linking, images/artifact storage, graph relations, adaptive tool calls and image inspection. **Impact:** future only.

## 5. Track, Then Bind — object identity can require an earlier visual moment, not more context
**Class:** future perceptual source-grounding challenger. **Submitted:** October 22, 2026. **Primary:** https://arxiv.org/html/2610.31471v1

**Method:** Run a visual tracker over full video, find a time window where an entity can be semantically identified, bind that description to a tracker ID, then answer from a compact identity/track record instead of re-showing full distracting video. **Evidence:** On synthetic cup/card games, Qwen3-VL-8B approach reaches 100% and real Perception Test cup 32B 52.3 vs direct 35.5%; when an 8B reader is asked the original question over the full video without bind, synthetic cup/card only 44%/40%; readout with the original video 38%/72% vs 100% with bound facts. Not a broad video QA improvement: Video-MME overall 70.9% vs direct 71.9%. **Limitations:** existing tracker error/occlusion, ambiguous binding, multiple VLM calls plus SAM2.1; experiment is on objects, not person identity or consent. **Already covered:** source-grounded perceptual personal memory, source-native media, dynamic entity/state graph. **New:** select *where* in observation history object identity is resolvable and persist a provisional track/evidence binding, preventing long-video answer interference. **Action:** future targeted multimodal identity test; never promote visual track to authoritative host/person identification or permission without corroboration. **Impact:** future.
