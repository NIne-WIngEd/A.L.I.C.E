## 1. Concordat — protocol-typed agent sessions and structural action admission

**Primary:** [Concordat: Typed Sessions for LLM Agents](https://arxiv.org/html/2610.37461), newly surfaced Oct 28; [implementation](https://github.com/miladsikaroudi/concordat). **Class:** direct future Mission execution / authority-contract qualification improvement, **not** an observed current defect.

**Method:** Protocol `(S,A,s0,F,delta)` defines legal actions by session state. Agent classes expose only state-legal tools each model turn, and a separate runtime monitor rejects illegal invocations before side effects. `@human` transitions are non-model decisions; budget tokens/tool calls are charged and handed off linearly. Definition-time reachability/dead-end checks and parent–child protocol trace inclusion stop a subclass silently bypassing a parent approval route. Approximately 850 Python lines, optional OpenAI/Anthropic runners, 50 unit tests. Parallel tool calls disabled to preserve state ordering.

**Evidence/ablations:** In 50 airline tasks with pressure to skip confirmation, ordinary agent made unconfirmed changes in 13/50 GPT-4.1 tasks and 29/128 Claude Haiku 5.5 runs, versus 0 for Concordat. Task success GPT 20/50 standard, 22/50 constrained; Haiku 112/128 standard vs 105/128 constrained. Outcomes often rated standard agent successful despite policy violations. This is a matched protocol-vs-no-protocol comparison, not proof against all adversarial bypasses.

**Already covered / genuinely new:** A.L.I.C.E. has owner authority, Mission Graph, permission checks, workflow receipts and memory/Claim separation. The useful mechanism is **provider-independent structural admission of tool choices and safe protocol refinement**. No new authority plane or graph system.

**Authority/privacy/deletion/rollback:** Approval must be bound independently to the actual host, exact action/scope, time and revocation. **The paper's benchmark classifies “yes/yep/yeah” in a customer message as approval; that is NOT trustworthy human attestation** and does not solve the previously tracked I-HITL attack. Tool availability and state are projections of canonical permissions. Rebuild after permission change, pause on revocation, preserve action receipts and side-effect idempotence. Risks: brittle state machine, false approval attribution, serial tool-call latency, incomplete formal proofs of surrounding application. **Action:** When real Mission tool execution crosses this boundary, one targeted test of state/tool gating plus separate signed/owner-bound approval, revocation, and nonduplicated side effects. No framework adoption yet.

## 2. EvoSpeakerMem — lifetime speaker continuity without treating a voiceprint as identity authority

**Primary:** [From Voiceprints to User Entities: Online Speaker-Memory Construction for Multi-User Spoken Agents](https://arxiv.org/html/2610.36713), Oct 27. **Class:** future perceptual identity and source-person/host separation challenger.

**Method:** Session diarization and ECAPA voice embeddings propose links into persistent speaker entities. Separate link threshold and stricter template-update threshold reduce acoustic drift; chronology is processed causally without knowing future speakers. Entities bind audio observations, transcribed turns and derived per-person memory. Evaluates fixed, online-mean, gated update, all-exemplar KNN; synthetic-voice LoCoMo-ID clean and microphone/room-shifted conditions, and real multi-month SMIIP-TV recordings.

**Evidence:** Fixed enrollment voiceprints' below-threshold genuine trials rise from 29.8% in <=1-day recordings to 55.6% at 365–450 days. On 4,113 identity-sensitive queries, ECAPA identity-gated QA rises from 71.41% fixed to 75.27% gated on clean and from 60.15% to 71.77% under shifted synthetic audio. Under these controlled settings gated update yields 0 wrong private-access authorizations (vs 1 fixed shifted and 115 plain online update); it is **not** a security proof. All-exemplar KNN increases clustering recall while causing more wrong-person links. Measured ECAPA embedding time 65.6ms/turn **excluding** STT/diarization/memory/QA.

**Already covered / novel:** Fable requires perceptual memories, distinct host/source-person/self, identity-grounded Claims and private access. New is **longitudinally maintained noisy speaker links as revisable perceptual evidence**, with different thresholds for linking observations vs updating their template. This must **not** become a deterministic identity key or authorisation factor.

**Risks/assumptions:** Synthetic voices, two-speaker main collections, no real overlapping household conversations, attack/spoofing and consent not demonstrated, templating can contaminate and all-exemplar grows without bound. Voice biometrics require explicit consent, local-only custody and documented retention/deletion/rollback; disputed links cannot silently merge people's Claims. **Action:** When authorized multi-user audio enters actual ingestion, a small longitudinal correct-link / false-link / abstain check, source-person partitioning and deletion propagation. No new plane, speaker-count ceiling or biometric authority.

## 3. PIP-ToM — evidence a person could access is not all evidence the assistant knows

**Primary:** [Who Knows What—and What Does It Support? Perspective-Bounded Evidence Calibration for Multimodal Theory of Mind](https://arxiv.org/html/2610.36824), Oct 27. **Class:** future social/relationship perspective-model capability improvement.

**Method:** Reconstruct multimodal event traces but form per-agent evidence stores containing only observations accessible to each subject. Couple that to typed mental-state hypothesis / source-route matching; use evidence admissibility and diagnostic relevance to calibrate a model-based Bayesian inference. Separate observed world truth from subjective belief and from inference about hidden goals.

**Evidence:** GPT-4o system scores MuMA-ToM 92.56% vs AutoToM 81.44%; MMToM-QA 95.00% vs 83.00%; Hi-ToM 95.00% vs 72.50%. Removing perspective storage reduces false-belief and multi-agent predictions; in a manually audited 121 improvements, 62.8% of ablated failures exploited inaccessible/global evidence. Removing claim-aware calibration drops MuMA social-goal 84.33→67.67% and MMToM goal 90.33→70.50%. Direct evidence matching is weaker on latent goals than Bayesian fallback (65.95% vs 84.35%), so source matching alone is not mental-state understanding.

**Already covered / novel:** Distinct host/source-person/self/relationship models, temporal Claims, Episode provenance and Cognitive Multi-Graph exist in Fable design. New future invariant: **infer what X knew only from temporally and perceptually accessible X-perspective evidence**, not ALICE's omniscient global record; infer goals separately and keep uncertainty.

**Limits/cost:** Video/text event extraction and Bayesian hypothesis scoring are model-invocation heavy; structured benchmark tasks with simulated agents not actual host relationships; per-subject access must not turn inferred thoughts into canonical Claims. Correction/deletion/revocation and identity-bound access apply. **Action:** When social/relationship modeling becomes operational, one epistemic-perspective test with withheld/unseen event, source-person correction and unknown/abstain, not a fixed mental-state ontology.

## 4. DiscernMem — wrong memory content versus right memory in the wrong context

**Primary:** [Remembering Is Not Enough: Refining Memories and Learning When to Use Them in Multi-Agent Systems](https://arxiv.org/html/2610.36652), newly surfaced Oct 28. **Class:** future procedural memory / outcome attribution challenger.

**Method:** Versioned role-owned rules have separate content and meta-memory of application/avoidance conditions, effects and prior corrections. Defect-Aware Memory Refinement replays a full collaboration with **one** memory versus none at fixed seed, diagnosing actual rule defects and validating repairs against both current and earlier tasks. Boundary-Learning Meta-Memory updates role/preaction-context conditions determining when a retained correct rule should be used or avoided. Keeps backbone fixed.

**Evidence/ablations:** Qwen3-4B-Instruct across AutoGen, CAMEL and MacNet, four QA/code/planning tasks: averages 59.03/56.93/59.67 (0.51–4.32 points over strongest respective baseline). CAMEL PDDL reaches 37.71 vs 28.48. On AutoGen PDDL, full 29.15, without use-boundary filtering 27.40, without repair validation 26.31, without both 25.36. Single-memory paired effect is **not** causal marginal contribution in a multi-memory set. Team replay costs rise with touched memories and may be impossible or unsafe for irrevocable personal actions; task/evaluator scope narrow.

**Existing/new:** A.L.I.C.E. already separates evidence, Claim truth, procedural skill versions, MRM utility and Mission outcomes. The new useful discrimination is **rule-content repair versus role-specific applicability repair** while protecting known-good prior behavior. A failed task cannot by itself prove one recalled fact false.

**Governance/action:** Replay only simulation/authorized reversible state, never real irreversible operations. Keep experience and historical versions; preserve actor/subject/source lineage and correction/deletion/rollback; meta-memory utility is neither truth nor authorization. **Action:** Reserve for a demonstrated wrong-skill-reuse failure in the actual Experience → procedure → Mission loop; focus a few matched cases, no all-pairs or current MFM change.

## 5. Task Advancement Memory — verified local progress becomes reusable procedure

**Primary:** [From Interaction to Capability: Task Advancement as State and Supervision for GUI Agents](https://arxiv.org/html/2610.37482), Oct 27. **Class:** future Mission Graph and environmental/procedural memory improvement.

**Mechanism:** Maintain an explicit DAG-like task requirement state: an input drafted is not a submitted action, a click is not proof of its effect, and only observed confirmation retires a requirement. After execution, review interaction segments that achieved independently identifiable **local results**, including segments from tasks that failed overall. Learned reusable operations distinguish preconditions, data acquired during the operation, expected result and verification condition.

**Evidence:** On Qwen3-VL-32B MobileWorld GUI-only tasks: base 12.0% success, advancement state alone 28.2%, state+evidence 29.1%, +operator graph 32.5%, full 34.2%; strongest compared ConAct 29.1%. Lifecycle tokens per solved task 0.771M vs ConAct 1.257M (38.7% less), though extra post-task reviewer has real costs and failed-task overhead varies. SPA-Bench English Level3 57.0% vs GUI-explorer 53.7%. Multi-app success is more improved than single-app. Limited to simulated mobile GUI; model-judged confirmation can be wrong; no verified desktop/web transfer or long-lived operator maintenance.

**Already covered/new:** Mission Graph, Experience/outcomes, source-native action receipts, Temporal and procedural learning already intended. Novel transferable idea: **promote locally verified substep success without declaring global Mission success**, bind skills to precise observable outcome/precondition rather than a vague completed task. Distinguish projections vs actual side-effect evidence.

**Authority/deletion/rollback:** An observed UI message might not prove backend transaction; confirmations need source/receipt and permission scope. Revision/retraction of outcomes must invalidate learned operators and mission states; no user action replay without authorization. **Action:** When actual multi-app missions show progress-loss or procedural-learning failures, test one cross-app workflow with local outcome receipts and failed-global-task positive substeps. No new workflow engine.
