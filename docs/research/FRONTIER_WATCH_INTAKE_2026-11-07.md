## 1. PLatour / PACT-Check — improvement is not proof that one model contributed useful information

**Primary:** Zhenyi Shen et al., *On the Opportunities and Challenges of Prefill-to-Autoregressive Cross-Model Transfer*, arXiv:2611.06976v1, **submitted Nov 4, 2026**. https://arxiv.org/html/2611.06976

**Classification: Direct current capability-improvement opportunity in the planned FloRA evaluation design, not a demonstrated current runtime defect.** No edit to current training or evaluation pipeline is authorized or necessary until FloRA tests are being implemented.

**Method/assumptions:** Frozen large sender prefills a prompt; a small receiver generates autoregressively. Layer-corresponding zero-initialized linear projections inject sender hidden state into the receiver residual stream during prefill. Train only bridges using GRPO. The authors recognize that such a bridge can act as a prefix/adapter without actually conveying sender facts. Their PACT-Check therefore compares original transfer against (1) fixed dummy sender features, (2) irrelevant question features, (3) self-communication/receiver-as-sender, and (4) separately trained receiver-only LoRA/full fine-tuning. PACT-Score subtracts the *strongest* control from actual system accuracy.

**Experiments/ablations:** Qwen3 sender up to 235B / receiver 1.7B and Qwen3.5 hybrid models; ARC-C, MMLU-Redux, Chemistry, GSM8K, MATH, coding. Original generation gains versus receiver alone are **+27.86 pp Chemistry**, **+8.49 pp GSM8K**, **+4.80 pp MATH500**, but PACT-Scores over the strongest relevant controls are only **+3.34, +0.23, -4.05 pp**, respectively. In many domains strong receiver-side adaptation explains the gain. Dummy/irrelevant-feature probes, self-communication, direct receiver training, hidden-vs-KV, layer matching and projector initialization are studied. Trained bridges can carry hundreds of millions of parameters (one configuration 234.9M). Evaluation is task-specific and positive PACT-Score is evidence against *tested* alternatives, not proof of semantic information transfer in all circumstances.

**Already planned:** Native personal foundation verdict precedes replaceable GPT/Claude feature-model output; FloRA requires causal improvement from learned personal state versus direct personalization. **New:** a particularly sharp falsification control for claimed personal-foundation-to-downstream transfer. A downstream generator may improve after bridge/harness adaptation while using no relevant personal information. **Contract/identity/privacy:** Personal facts and judgment remain owner-scoped; sender/receiver internal activations cannot establish Claim Authority; provider privacy egress remains governed. Version bridge/adapters and test prompts for rollback; avoid exposing private representation state to an unapproved provider. **Upside/cost/risk:** Better causal attribution of actual judgment transfer; several extra *focused* comparator runs for a genuine FloRA claim. Full PLatour training is expensive and irrelevant to today's MFM native-generation failure. **Action:** At FloRA integration, add an invalid/absent personal-state control and a receiver-only adaptation comparison for one held-out judgment change. Do not start a PACT implementation or test campaign now.

## 2. Axis-LoRA — dense retrieval underweights time, location, person and event changes

**Primary:** Dohoon Kim et al., *Axis-LoRA: Probing and Adapting Embedding Models for Personal-Memory Retrieval*, arXiv:2611.07820v1, **submitted Nov 5, 2026**, EMNLP 2026 Main. https://arxiv.org/abs/2611.07820

**Classification: Future challenger** for multimodal/episodic vector candidate selection; no proven blocker with the selected Qdrant + exact/temporal graph system.

**Method:** Construct single-axis counterfactual training triples that alter an event's temporal, spatial, entity or action value while holding other text constant. Demonstrate that frozen embedding output barely moves for some changes and an output projection cannot restore missing discrimination. Probe attention heads, finding axis signals unevenly concentrated in late layers. Train four separate LoRA branches within the last ~20% of encoder layers with a per-query sparsemax gate; mix frozen embedding similarity with gated axis similarities. Preserve general retrieval using a distillation anchor. AxisCF contains roughly **4,196** training triplets.

**Evidence/ablations:** Three encoders, LongMemEval, ATM-Bench normal/hard and LoCoMo. Mean R@10 improvements **+1.56, +1.38, +1.28 percentage points**, with query-bootstrap CIs excluding zero; ATM-Hard improvement about **+2.4 to +3.8 pp**. A Qwen3-Embedding-0.6B ablation improves mean R@10 **0.589 -> 0.602**; without axis counterfactual supervision **0.593**, without KD anchor **0.588**, without query gate **0.599**. General BEIR-6 nDCG@10 falls from **0.5449 to 0.5399**, a modest regression. Explicit categorical-value swaps and small ATM-Hard sample limit transfer to indirect time/identity inference and open-world personal events.

**Already planned:** Bitemporal Claim Authority, subject identity, source-native/time filtering, Cognitive Multi-Graph, vector candidates under MRM/Recollection. **Genuine delta:** inside-encoder representational limitations even when metadata-aware retrieval ultimately could resolve them. **Authority/identity/deletion:** Learned similarity never determines who a person is, valid time, permissions, trust, or canonical truth. Store adapter/dataset lineage and support removing/rebuilding derived embeddings after correction/deletion. **Cost/risk:** Four conditional encoding branches, training, embedding regeneration, additional score operations and possible general-search degradation; no hardware tier may drop the logical vector plane. **Action:** Only if an observed personal episodic query misses correct evidence among same-topic time/person/place distractors *despite* existing exact/graph gates, compare a tiny axis-contrastive reranking intervention. Do not prescribe four fixed memory axes as Fable's ontology and do not reopen Qdrant selection.

## 3. ReConMem — cross-linking conversation decisions to changing code entities

**Primary:** Zhishuo Yang et al., *ReConMem: A Graph-Based Dual Memory System for Repository-Oriented Conversations*, arXiv:2611.07759v1, **submitted Nov 5, 2026**. https://arxiv.org/abs/2611.07759

**Classification: Future challenger** for source-native code retrieval and engineering Mission context, not a new Cognitive Multi-Graph backend requirement.

**Method:** Maintain interconnected semantic conversation memory and structural repository-code entities; synchronize edges between them. Retrieve with an original natural-language query plus a code-draft-aligned query, intra/inter-graph neighbor expansion and code granularity-specific compression. Code drafts are retrieval hints rather than committed code. Structured repo entities remain live/source-native.

**Evidence/ablations:** On LoCoEval, Pass@1 improves **+7.917 pp single-hop** and **+7.292 pp multi-hop** over strongest evaluated baseline. On CodeAssistBench, **27.61% Correct** and **44.03% Partially Correct**, **+4.10/+7.09 pp** over full-history. Ablating graph expansion, code-graph direct search, query grounding or hierarchical compression harms accuracy or efficiency. Retrieval completeness is assessed with LLM judges and source-identifier checks; results are benchmark/harness dependent. Memory writes and updates are not free: on LoCoEval mean tokens roughly **1.177M per single-hop conversation**, close to Mem0 R **1.171M**; on shorter CodeAssistBench ReConMem combined token cost **363.8K per issue** versus **325.6K** for full history. Maintenance adds ~38–39% of its total token usage in the analyzed long-horizon setting.

**Already:** Source-native/live reads and graph/associative projections, cross-turn context and durable Mission state are in the required architecture; source code is external evidence, not Claim truth. **New:** specific joint dual-query and code granularity recall strategy for iterative engineering decisions linked to live identifiers. **Compatibility:** Keep file/commit/branch/version-qualified provenance; record stale symbol renames or deleted code as corrected projections, never as a host identity/Claim update. Refuse linking private host information across unrelated source-persons or projects. Rebuild derived indexes on code changes/deletion. **Cost/action:** Only investigate after a real repo-centered Mission fails because its earlier discussion and code entity are not recollected together. No new store or permanent dual-graph ontology.

## 4. GapWiden / GapVeil — auditability is distinct from deletion, privacy leakage and utility

**Primary:** Piyush Tiwary et al., *Widen the Gap, Hide the Gap: Auditable and Indistinguishable Unlearning for LLMs*, arXiv:2611.05866v1, **submitted Nov 4, 2026**. https://arxiv.org/abs/2611.05866

**Classification: Future challenger** for verifying personal-weight deletion. Strong caution: suppressing a response is **not** cross-layer unlearning.

**Mechanism:** Evaluate eleven unlearning algorithms across four axes: forget quality, retain utility, external membership leakage, and *provider-side auditability* under an original-vs-unlearned log-likelihood statistic. GapWiden trains a hinge margin on forget-set audit gap while anchoring retain-set behavior. GapVeil samples generations from the **original base model** and rejects responses failing an audit-gap threshold using an unlearned model as detector. The original pretrained weights can therefore still contain deleted data.

**Evidence/ablations:** On TOFU, reported auditability and measured leakage approach retain-only oracle levels after the two-stage method, with average forget/retain improvements in evaluated configurations. Ablations vary audit margin, rejection threshold and number of resamples; stricter thresholds improve suppression but add calls and can discard useful content. On MUSE News, **retain performance falls 0.569 -> 0.380**, and on Books **0.420 -> 0.400**. That explicitly contradicts any blanket claim of no utility tradeoff. Model/data/benchmark assumptions and rejection sampling do not prove semantic deletion or protection under adaptive extraction.

**Already:** Owner-governed deletion across raw evidence, projections, indexes, datasets, weights, running activation state, federated copies and influence echoes; content-addressed lineage/rollback. **New:** internal owner-readable audit statistic can be valuable, but must remain separate from adversary-facing behavior and from proof that the model actually forgot. **Compatibility:** Never promote an inference-time filter to a deletion receipt; never use original unredacted model as a permissible post-deletion execution source without governance. Sign retained lineage and validate all output channels, plus post-deletion re-learning. **Cost/risk:** Additional model training, dual-model access and multiple sampled generations at serving time; retention regression and possible membership channels. **Action:** Future unlearning evaluation should assess provider-side audit evidence separately from retained utility and influence-echo behavior. Do not install GapVeil in current architecture.

## 5. Interactive backdoors — poisoning can steer multi-turn judgment, not just one response

**Primary:** Zhiyang Xia et al., *Interactive Backdoor Attacks in LLM-Based Proactive Dialogue Systems*, arXiv:2611.06969v1, **submitted Nov 4, 2026**. https://arxiv.org/abs/2611.06969

**Classification: Future challenger** for personal-model learning admission and long-Mission behavioral integrity. Distinct from Memory Trap's benign overgeneralization and from cross-session *external-memory* injection: this threat is planted **during fine-tuning** and remains latent until a trigger.

**Method:** Attacker contributes a small number of seemingly ordinary dialogue examples to a fine-tuning corpus. Three post-trigger cases: immediate answer deviation, prescribed progressive steering over multiple turns, and unconstrained steering under evolving user replies. The target is a guidance policy, not merely copying a malicious snippet into prompt context.

**Evidence/ablations:** Two 7–8B instruction backbones, two simulated counseling dialogue datasets and supplementary interactive teaching transfer. On PsyDT, at **500 injected dialogues / 0.58%**, direct attack success reaches **84.33% Llama3-8B** and **91.79% Qwen2-7B** versus 0% unpoisoned controls; the dose-response from 100 to 500 examples and progressive-attack scenarios is analyzed. Tested training-data filters fail to reject many examples, and output/post-hoc defenses leave residual success. Synthetic counseling judge-defined attack success and specific backbones mean these percentages are not deployment-wide personal-assistant probabilities.

**Already:** Curated source/dataset provenance, model lineage, governed learning and rollback, owner authority, independent Mission permissions and judgment-state separation. **New:** low-rate seemingly benign dialogue training data can modify *multi-turn steering policy* without needing further injected prompts. **Compatibility:** A model-learned tendency does not authorize external actions, overwrite source-person/host state or nullify a correction. Reject unknown-license/unknown-origin training, keep per-sample lineage, and ensure authorized training-set revocation can trigger targeted requalification. **Cost/action:** Future one-case policy-poisoning test only when actual personal-model fine-tuning from third-party dialogue is admitted; no new defenses or preemptive model retraining now.

## 6. Octopus — GPU-resident branching context with controlled cross-branch influence

**Primary:** Tianming Sha et al., *Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning*, arXiv:2611.06956v1, **submitted Nov 3, 2026**. https://arxiv.org/abs/2611.06956

**Classification: Conditional future model/serving challenger**, not an infrastructure reopening. **Method:** GPU-resident DAG of immutable KV cursors; zero-copy prefix forks; recurrent-state-preserving rewind; attention-only KV mounting across sibling branches; packed DAG-GRPO and leave-one-branch-out credit. Five primitives: fork/read_thread/wait/rewind/commit. Selective attention-layer mounting avoids overwriting hybrid recurrent state, but server kernels, scheduler and training protocol must be co-designed.

**Evidence:** With Qwen3.5-4B under sparse BM25, BrowseComp-Plus **49.6%** vs single-agent GRPO **32.1%** at 143K context, and OpenResearcher **51.2%**; reported **3.3x** training throughput and **2.8x** lower peak KV memory, attention-only sharing reduces measured off-task hijack **57.9% -> 2.7%**. Single-family benchmark setup, very specialized kernels and GPU constraints reduce external validity; dynamic cache sharing can leak data between owner-scoped branches if access boundaries are weak.

**Already:** Mission Graph + Cognitive Workspace + durable branch history and owned provenance independent of serving model. **New:** potential efficient within-model parallel exploration and a useful isolation failure diagnostic for hybrid attention/recurrent models. **Authority/identity/deletion:** KV cursors are transient execution state, never Experience truth or Mission authorization; prevent branch cross-owner exposure, apply revocation/replay to caches, and preserve durable receipts separately from GPU state. **Action:** Only revisit if a selected private inference model shows material multi-branch latency/KV cost that cannot be solved through normal placement/scheduling. No current model, server or GPU change.

In tested dense models and constrained single-GPU batch shapes it provides bitwise consistency and **53.5–55.0% lower time / 115.2–122.2% higher output throughput than vLLM Batch-Invariant**, but a different comparison against standard vLLM has only **5.4–6.9% latency overhead** and does not make ordinary inference faster. Use only if an actual judge/fixture conflict arises, not a new evaluation campaign.

Task-local online harness edits based on offline contrastive guidance can improve coding-agent benchmarks, but its decision value is already represented by Reglos/Evolver and the no-blind-hotfixes rule. No open-ended code self-modification or new harness loop.
