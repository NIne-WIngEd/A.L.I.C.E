## 1. Anthropic — The components of agent memory (November 6, 2026)

**Primary:** Anthropic Engineering (Lance Martin et al.), *The components of agent memory*, posted **Nov 6, 2026**, https://www.anthropic.com/research/components-of-agent-memory . This is a first-party research/engineering report rather than a peer-reviewed controlled paper. **Classification: Already covered/corroboration with a future direct Lifecycle Curator / Memory Resource Manager / source-native recollection improvement opportunity.** Newly reported multi-setting evidence is strong enough to record; not a missing logical Fable plane.

**Mechanism and exact scope:** Agent creates selective notes during a session; original transcripts remain searchable. Between sessions an offline 'dreaming' agent checks notes against transcripts, corrects them, constructs and maintains linked wiki representations, and chooses which compact index/relevant material is injected into future sessions. The hierarchy is `raw transcript -> notes -> derived linked maps -> bounded working-context injection`. Wiki pages and injected indices are representations, not authoritative history. Research explicitly excludes parametric weight changes from its limited definition of 'agent memory', whereas Fable v1 *requires* parametric personal memory in addition to these nonparametric forms.

**Experiments/contrasts:**
- In a 30-question CL-Bench database task starting each answer in a fresh session but preserving an agent-managed folder, reported mean reward with vs without memory: Opus 5.5 **0.838 vs 0.655**, Sonnet 5.5 **0.833 vs 0.644**, Opus 5 **0.828 vs 0.564**, Opus 4.7 **0.700 vs 0.383**. Weaker Sonnet 4.6 improves little (**0.364 vs 0.330**) until explicit read/check guidance (reported **0.641**), showing learned salience/use matters as much as storage. Imposing 'record only failures' reduces memory benefit by **0.234** for Opus 5 and **0.150** for Opus 4.7. The source does not establish an invariant universal learning rate or say these are representative personal-model outcomes.
- A descriptive Pokémon comparison found an indiscriminate-note agent with **413 files / one badge**, versus a selective-note agent with roughly **10 files / four badges**, but different models and exploratory single runs confound causal inference. In a targeted memory-error experiment, an offline re-read of the transcript fixed a mistaken landmark note; the corrected run reached the destination while uncorrected and no-memory runs failed. Useful failure tracing, not a replicated reliability guarantee.
- With roughly **350,000 company files / 420M tokens** and **25 evaluation questions**, 128 agent dreaming sessions built a linked wiki. Wiki-only score improved from **13% to 48%** across construction; wiki **plus live search** improved from **54% to 61%**, versus **53% for search alone**. Wiki+search also saved about **20K answer-context tokens per query** in their setup. Figures indicate up to **128M offline dreaming tokens**, a substantial training-free maintenance bill, not a free optimization.
- On a cross-document legal task, wiki-assisted access improved graded criteria **87% vs 73%** for search alone. On another task largely answerable from one file, the wiki brought no clear advantage. A wiki sometimes grew **1.77x larger than its original documents**. In an inspected legal-brief case, concurrent edits to a shared terms table lost supporting facts (**41/57**). After changing wiki-writing instructions so independent documents owned separate pages and exact terms were preserved, **57/57** facts survived. This is a local task-conditioned diagnostic, not proof of generally lossless curation.
- The top-of-context index example is Claude Code's first **200 lines / 25 KB** of a particular file; this is *not* a Fable capacity or memory ceiling.

**Already covered in A.L.I.C.E.:** Raw Evidence/Event history with source-native reads; learned MFM proposals; dynamic episodes/semantic/cognitive multigraph; asynchronous Lifecycle Curator, MRM and Recollection; working/activation context; correction/deletion/rollback; bounded owner-authorized serving. MRM can schedule source lookups, derived maps and active context without changing selected stores. The Fable v1 personal foundation also needs host/person/social/mission/skill state and model weights, which the report does not attempt.

**Genuine new delta:** Primary evidence for (1) *retrospective transcript-backed error correction* of agent-authored notes; (2) additional value of linked *derived maps plus source-native search* particularly for multi-document synthesis; (3) the tradeoff between smart write-time salience and offline compute; and (4) *concurrent curation write-loss* as a concrete failure mode. It also demonstrates that arbitrary extra procedural constraints can degrade good salience selection, yet weak writers may need explicit prompts.

**Authority, identity, deletion and rollback:** Original authorized Experience remains the evidence record. Dreaming-generated wiki and preloaded index are versioned derived projections with source IDs, owner scopes, valid-time/trust checks, and curation receipts. A wiki inference cannot become an XTDB Claim via copying. Never use a stale injected rule as a standing Mission permission; recheck live authoritative source and tool authorization before consequential action. Reject curation across host/source-person identity boundaries. Conditional notes must not survive owner revocation; deletion cascades to maps, search indices, cached preloads, training derivatives and federated copies with model-lineage follow-through. Curation concurrency should preserve generation/expected-revision or per-source isolation and support rebuild/rollback. No irreversible consolidation or dropping original raw evidence merely because a wiki performs well.

**Upside/cost/evidence:** Better cross-episode error recovery and multi-source synthesis with less read-time context; offset by **very high offline model-token cost**, graph-map storage, maintenance drift, stale preloads, write races and uncertain transfer to private personal workloads. Multiple evaluated models/benchmarks but some central mechanistic examples are single traces, some comparisons confounded, and results are vendor-reported without independent replication.

**Concrete action:** Research/context only. When a real A.L.I.C.E. curation or multi-source answer failure appears, compare *source-native only* vs *source-native + versioned linked derived map* on that failed case; include evidence freshness, curation write concurrency and any necessary citation/authority check. For a recurring miswritten note, try a single transcript-backed deferred repair, verify the precise correction and impact, and stop if it does not change the next engineering action. Do not create a generic nightly dreaming service, copy a wiki storage backend, pre-inject 200 lines as a product limit, run repeated 128-pass sweeps or interrupt current native MFM formation.

## 2. WASP-Mem — diagnosis quality outweighs repeated self-review for procedural learning

**Primary:** Peizhi Niu, Ge Shi et al., *WASP-Mem: Let Agent Organize Procedural Memory. Human Spend Effort on Diagnosis*, **arXiv:2611.04003v1, submitted Nov 2, 2026**, https://arxiv.org/html/2611.04003v1 . Newly surfaced this watch; not in November 2–7 intakes. **Classification: Future challenger for procedural/environment memory and Mission-skill learning, with specific diagnostic guidance.** This is a preprint, not independent deployment evidence.

**Mechanism:** Fixed model and harness; execution traces plus outcome/diagnostic feedback are consolidated after a run into agent-organized, interlinked procedural wiki pages. An index plus semantic search and page-link navigation retrieve conditions, actions and repairs for future runs. The consolidator can create/update/split/delete pages and lint conflicts. Paper compares unconstrained Free Form pages against prescribed procedural/action/lesson schemas, explicit post-hoc dedup, flat insights, SkillX skills, or raw logs. Crucially it varies feedback source (agent self-judge, external checkpoint outcome, human cause-and-repair diagnosis), ingestion of only successes vs successes+failures, and 1–4 rounds.

**Evidence and ablations:**
- TheAgentCompany contains **127 tasks / 542 state-verified checkpoints**. Three model families using the same 127 tasks across training and test rounds: Free Form checkpoint success **72.3–72.5%**, about **4.6–6.1 pp above the strongest compared baseline** and with **57–61% less storage** than that baseline. Free Form procedural store size around **233–255 KB**, much smaller than raw traces. Prescribed schemas decrease checkpoint success by **2.1–6.1 pp** against Free Form and explicit dedup does not restore it.
- A more legitimate held-out test, tau2-Bench Retail, uses **74 training / 40 disjoint test tasks** with shared task procedures. For Claude Opus 4.6, Free Form and SkillX tie at **81.2% checkpoint success**; for GPT-5.4, Free Form **76.6%** vs SkillX **69.3%**; for GLM-5, Free Form **58.3%** vs SkillX **53.1%**. This indicates some in-domain transfer, not broad cross-domain lifelong learning.
- Both success and failed traces with **external checkpoint feedback** improve checkpoint success **7.4–8.1 pp** over self-judgment. Adding human natural-language failure diagnosis improves another **3.5–4.4 pp**. Under self-judgment alone, adding failed traces brings approximately no benefit; with checkpoint plus human diagnosis, adding failures yields **9.6–10.5 pp**. After one diagnostic round, performance **75.8–77.1%**, exceeding four self-judge rounds by **7.0–10.9 pp**. Under human diagnosis R4 reaches **85.6–86.7%**, but those rounds recycle the same tasks, so gains are not proven broad skill generalization.
- Costs are material: a 127-task evaluation batch takes about **12 wall-clock hours** on the paper's setup; annotating one batch's failures needs roughly **6 human hours**. The paper lists free-form per-batch execution+retrieval API cost roughly **$149.3 Opus / $147.8 GPT / $65.9 GLM**, excluding consolidation, embedding, human work and hosting. Per-configuration stochasticity is not quantified (single run); small deltas remain unresolved.

**Already:** Experience Ledger with verified outcomes and failure localization, Mission Graph, skill/procedural state, dynamic cognitive graph associations, source-native access, lifecycle curation and governed personal-model training. Recuris/FRESH/Evolver/DiscernMem already captured portions of precondition/repair and failure diagnosis. The genuinely additional evidence here isolates *external failure diagnosis vs extra self-replay*, plus *agent-chosen structure vs prescriptive page classes* under fixed harness, including resource costs.

**Authority, provenance, identity, deletion, rollback:** A procedural wiki page is a derived candidate, not canonical Experience, adjudicated Claim or owner permission. Preserve exact tool receipts, scope, preconditions, source versions, actor/subject identity, permission epoch, outcome and diagnostic provenance. Keep false/overgeneralized repairs reversible. Human diagnosis is evidence with an attributable source, not universal truth. Skill consolidation must not cross hosts or redistribute confidential operational details. Correction/revocation must rebuild or retire dependent skills, indexes, future prompts and trained descendants. Fixed Free Form wiki structure is an experimental representation, not a Fable skill schema or model-count ceiling.

**Upside/risk/action:** Stronger procedural transfer under recurring workflow failures and fewer repeated blind fixes. Risks: hallucinated diagnosis, overgeneralized skill rules, leakage in rich traces, setup cost, one-run evidence and repeated-task leakage. **No current action:** When real durable Missions exhibit repeated state-dependent tool failures, capture one external verified outcome plus one accountable cause/precondition/repair diagnosis. Compare future behavior with the *same* underlying agent using the verified repair; retain rollback if the repair harms earlier skills. Do not create a broad enterprise task benchmark, relaunch MC10-style validation or reorder the current MFM learning plan.
