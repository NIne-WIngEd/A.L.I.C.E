## 1. ENGRAM — teach from experience, but prove weight competence before releasing retrieval

**Primary:** Ruiyi Yang et al., *ENGRAM: From Agent Experience to Weights through Verified Consolidation*, **arXiv:2611.09472v1 (Nov 6, 2026)**, https://arxiv.org/html/2611.09472 . **Classification: future challenger for procedural-to-parametric consolidation, MRM scheduling and Lifecycle Curator; not current MFM formation repair.**

**Method and assumptions.** The Engram Trace Graph (ETG) binds skill prerequisites, tasks, observation-action traces, applicability, outcome and source/episode provenance. A *demonstration-aware admission* gate chooses training examples either because the student has sufficient mastered success or because independent stronger teacher demonstrations were successful. Admission and release are distinct decisions: eligible skills supply supervised action targets to a low-rank adapter; separately reserved skill probes compare the **updated model without episodic retrieval** against a **base model with retrieval**, require that the skill really participated in training, and enforce both an absolute floor and relative criterion. Only qualifying skills move past ETG records out of *deployment retrieval* (possibly with residual records). Unqualified skills keep external retrieval. Archived/replay records persist separately.

**Measured evidence and ablations.** Qwen3-8B ALFWorld success **90.3±1.5%** vs MAGE **87.3±1.8%**, WebShop **83.4±2.4%** vs MAGE **84.0±1.8%** (not a universal win); HotpotQA F1 **71.5±1.0%** vs EmbQA **55.8±0.9%**; WebQuestions F1 **53.7±1.1%**, FinQA **69.3±1.7%**. Matched ablation ALFWorld: full 90.3, mastery-only admission 85.8, frozen ETG weights 82.1, no activation gate 87.3, SFT/no inference ETG 85.1. Fixed HotpotQA checkpoint with 600 records: retain all F1 **71.1** (600 retrievable); immediate release F1 **66.8** (13 retrievable); random release **67.6** (269 retrievable); **verified release 70.9** (269 retrievable, **331 archived**), paired ΔF1 **−0.2 pp, 95% CI [−0.6, +0.2]**. That interval does not prove zero degradation, and moving records to an archive is neither physical deletion nor total-storage reduction. ALFWorld Engram uses fewer input tokens (46.5k vs 81.24k base+ETG) and fewer calls (25.5 vs 29.5) but is **slower** (65.91 s vs 43.76 s); do not claim universal latency reduction. A separate WebQuestions condition does reduce latency (1.26 s vs 1.67 s). Llama-3.1-8B comparisons provided. Some paired confidence intervals resample instances at one checkpoint seed, not independent models, and baseline reproductions are authors' implementations.

**Existing coverage vs genuine novelty.** Fable already explicitly selects external/episodic/parametric/working memories, MRM, skill state, Experience Ledger, correction/deletion lineage, rollback and owner-governed training. New concrete operational method is **per-skill separately verified admission vs retrieval-release**, conditioned on *weight-only* held-out behavior and contribution to actual training. It distinguishes optimizing the model from proving successful internalization; not a new database, model-count limit, or consumer release tier.

**Governance / risk / cost / action.** Original Experience and raw authorized evidence remain canonical, separately retrievable/inspectable and subject to owner deletion; ETG is an evidence-linked projection. Releasing an ETG record from default retrieval is *not* permission to delete the evidence, claim, supporting history, archive or backup. Nor is success on skill probes authorization for the action, source promotion, inter-host sharing or continued use after revocation. Any evolved adapter requires source/method/model lineage, independent held-out generalization, correction/deletion and rollback. Teacher acquisition, ETG maintenance, per-skill probes and additional SFT are expensive; skill boundaries and reserved probe leaks threaten validity. **Future-only action:** once native personal formation and governed personal-model updates work and a real procedural retrieval-cost/transfer case exists, compare learned native actions *without the record* against the same baseline *with the record*. Keep one validated residual/rollback path and record measured serving latency, **total** retained bytes, archived bytes, and influence-echo behavior. No change to current 16-step MFM continuation.

## 2. From Procedures to Permissions — teach subagents least-privilege resource scopes from skill operations

**Primary:** Wenkai Yu, Ning Ding, Wentao Zhang, Yehui Tang, *From Procedures to Permissions: Learning Precise Subagent Authorization from Agent Skills*, **arXiv:2611.08905v1 (Nov 6, 2026)**, https://arxiv.org/html/2611.08905 . **Classification: future challenger for Mission Graph delegated execution/skill-state authorization, not a currently missing authorization root.**

**Method.** Derive tasks and step-by-step operational procedures from skill descriptions, execute through nested agents in interactive workspaces with explicit tool and file scopes, independently judge execution/authorization traces **without the synthetic SOP**, and train a subagent manager via SFT on accepted trajectories. This learns both task assignment and resource-scoped delegation instead of relying on task success alone. Works only if skill specs, synthetic trajectories, judge decisions, and granted tool interfaces reflect the real environment.

**Evidence.** On ClawArena-Team with Qwen3.5-35B-A3B, tool permission precision **59.9→73.3% (+13.4 pp)**, workspace permission precision **35.4→59.5% (+24.1 pp)**, task completion metric TCR **45.0→56.6% (+11.6 pp)**; Qwen3.5-4B also improves. Removing procedural guidance reduces tool/workspace permission precision to **63.6/38.3%**; removing independent verification to **57.7/30.5%**; removing explicit permission supervision to **50.9/27.0%** vs full **73.3/59.5%**. Terminal-Bench2.1 **28.1→34.8%**, SkillsBench **5.7→10.3%** for the larger model; TMAX outperforms on Terminal-Bench2.1. Many rejected synthetic rollouts indicate real data-generation/verification cost. Results are task- and judge-dependent, not live organizational permission safety.

**Existing coverage/new/gates.** Fable already separates owner-granted Mission authority from tools, procedural state and external agent suggestions; prior watch tracked task-graph privacy and cross-interface authorization. Novel is **trainable fine-grained resource-scope prediction** using procedurally grounded supervision. A skill file or synthetic SOP is not an authority grant. Suggested permissions must be intersected with current owner grant, source access class, recipient/egress permission, action consequences and revocation state by independent hard enforcement at execution/commit. The downstream agent never inherits ambient access or the host's full raw evidence automatically. An observed success is not proof of least privilege.

**Cost/decision/action.** Offline synthesized trajectories, verification LLM, SFT and deployment prediction add compute; risks include mis-scoped documents, inaccessible needed files and leakage of names/inferred source details. **Future-only:** when real delegated Missions operate, test exactly one over-broad source directory grant and one insufficient grant, compare learned proposals with authoritative policy, verify a revoked grant is rejected at commit. No replatforming or retraining now.

## 3. When Feedback Becomes a Backdoor — the evaluation reference can poison an evolved skill

**Primary:** Louise Nayeong Koh et al., *When Feedback Becomes a Backdoor: Tracing Backdoor Skill Formation in Text-Space Skill Optimization*, **arXiv:2611.09348v1 (Nov 6, 2026)**, https://arxiv.org/html/2611.09348 . **Classification: future skill-evolution / learning-data integrity challenger.**

**Method.** In text-based SkillOpt an adversary changes a subset of external *reference answers*, not the final skill file, optimizer or deployed model. The skill learner judges earlier responses against those references, reflects, proposes edits, merges/ranks them, selects candidates against validation, and persists the winning textual skill. Authors trace **recognition → exact proposal → merge → ranking → candidate → winner → retention → held-out activation**, with separate diagnostic and natural-run evidence classes. Poisoned training labels can induce a behavioral conditional while clean validation still rewards unrelated useful edits.

**Evidence and limits.** SearchQA natural full runs: 400 examples, 30% poisoned references, *clean* validation, three data seeds; all three final skills activate the attack response **200/200 triggered** held-out questions while **0/200** clean questions trigger. At seed 42, clean accuracy during training **169/200** vs benign baseline **171/200**; deleting the exact malicious rule eliminates activation **200/200→0/200** with held-out clean unchanged, strong local necessity. But in a *tool-mediated spreadsheet* setting, natural reference-poisoning runs did **not** retain an exact rule across three seeds and **0/120** target actions occurred. Only a specific diagnostic intervention enabled **32/40** activations in one seed; cannot generalize SearchQA rate to all skills. Tests use artificial trigger/payload and limited independent seeds. Attack rate conditional on poison dosage and validation selection.

**Existing coverage/new/authority/deletion.** A.L.I.C.E. already governs source provenance, outcome ledger, procedural learning, model lineage, corrective edits, and previously tracked prompt/memory/training poisoning. The **new entry point** is reference/validator ground truth, which can itself be adversarial or mistaken and can be promoted into a *persistent instruction* despite benign task success. Outcome, independent evidence and adjudicated feedback must retain separate provenance/authority. A test pass does not authorize behavioral edits or a standing user preference. All procedural promotions must be versioned/rollbackable and check source-person/host/A.L.I.C.E.-self boundaries; malicious instructions must be removed from current skill projections and evaluated for influence echo in any parametric derivatives. **Future-only action:** when skill evolution actually promotes procedures, test one poison-bearing contributed feedback label against verified environment outcome, compare frozen behavior with/without suspect rule, ensure no promotion solely from benchmark scores. Avoid new general red-team campaign now. No current MFM objective change.

## 4. Where Should Learning Live? — candidate selection, available forms and persistent history are different costs

**Primary:** Jungtaek Kim et al., *Where Should Learning Live? Regret Analysis for Text, Parameter, and Joint Adaptation*, **arXiv:2611.09701v1 (Nov 6, 2026)**, https://arxiv.org/html/2611.09701 . **Classification: conditional future challenger for Memory Resource Manager and governed personal-model evolution; theory-led, no current implementation decision.**

**Method.** Given *preconstructed* prompt/retrieval-text and parameter-adapter candidates, selection compares against fixed joint text+weight pairs that would have been deployed from the beginning. Regret decomposes into selection error **within** chosen family, omission of better cross-family choices, and signed effect of the actual persistent agent/environment history. Proves conditional bounds for independent exogenous loss functions, bounded influence and access to every candidate's counterfactual fixed-configuration performance; separately analyzes costly probes and deployment-only feedback. Cannot infer how to generate good candidates or assume these counterfactual histories are observable in real personal deployment.

**Experimental signal.** Qwen3.5-9B Spider SQL (six text, four parameter, 24 joint candidates): text-only selection can have lower within-family regret but **more total failures** because its candidate family excludes better configurations. SParC recursive dialogue tests indicate fewer prompt/adapter switches can improve *or worsen* outcomes depending on inherited state. Controlled tables separate selection vs state effects, not a general policy for lifelong host adaptation.

**Fable implication/governance/cost/action.** Fable already has multi-form memory scheduling, working state, versioned adapters, lineage and rollback, so no new plane. New useful distinction: a low measured within-form scheduling error does not prove the selected memory form is adequate; and rollback/replacement can alter next-task context even with equally capable candidates. Current Claim Authority and owner permissions remain independent of the selector; every adapter/prompt change requires recoverability and cross-layer correction/deletion. Full diagonal counterfactual feedback can be prohibitively costly and artificially unrealistic; no Cartesian all-pairs. **Future-only action:** if actual host-model switching shows regression, diagnose one real case with candidate restriction versus state carryover. Otherwise park.
