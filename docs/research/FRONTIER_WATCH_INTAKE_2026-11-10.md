## 1. SoMem — Can LLM Agents Organize Their Own Memory?

**Primary:** Zichuan Fu, Junjia Qi, Wenlin Zhang, Yimin Deng, Shirong Wang, Jinyang Li, Xian Wu, Xiangyu Zhao, arXiv:2611.11929v1, first submitted **November 9, 2026**, https://arxiv.org/html/2611.11929v1 . **Classification: future challenger (also corroborates existing source-backed reconstructive curation), not a new plane.**

**Exact method.** Separate immutable Source interaction records from agent-editable linked Markdown Topic documents, plus bounded Core of frequent preferences/requirements. Each Topic statement has source IDs and event-time annotation, with stable paragraph IDs and paragraph-to-paragraph links. Agent may split/regroup/revise topics. Runtime stages edits and validates structure, Source immutability, resolvable evidence annotations and link targets; upon acceptance it deterministically rebuilds relations Graph/backlinks, event-time Timeline, and Recent views from Topic. Query agent chooses semantic/lexical Search, List, and Read to inspect Topic, linked neighbors and the original Source. A generated Topic is an evidence-referenced projection, not Claim truth. Fixed-weight models in this paper; cross-reader reuse of stored workspace is not learned-judgment transfer.

**Methods/evidence/ablations.** Comparable primary experiments hold GPT-6 Luna as both Writer/Reader across methods; LLM judge used without systematic human calibration. LoCoMo all 1,540 questions: **88.96%** SoMem, **86.30%** E-mem, **80.32%** Mem0, **84.22%** full context. BEAM-100K 400 questions: **54.02** overall nugget vs strongest listed **50.92**, pass **61.50%**. LongMemEval-S 500 questions: **76.50%** vs LightMem **74.50%**. Frozen-memory LoCoMo ablations: full **88.96**; remove Topic **86.04**; remove Source **80.32**; remove Core **88.96**; remove Recent **87.66**; remove Timeline **87.99**; remove Graph **88.05**. Source and Topic effects stronger; individual derived access views' modest changes within sample uncertainty: **not** evidence a graph or temporal capability can be removed from Fable. Frozen GPT-5.6 Luna Writer memories reused with GPT-5.6 Luna Reader **92.34%** or Qwen 3.8 Flash Reader **93.25%** on LoCoMo. These are Reader QA accuracies, not identity or native learning fidelity.

**Costs and limits.** LoCoMo author-reported reference cost **$229.73** SoMem vs **$6.75** Mem0 and **$6.46** LightMem; **$118.85** one-time construction and roughly **$0.07/query**, highly dependent on cached-token pricing (revised estimate **$96.33** with aggressive caching). Selected readers averaged **5.2-7.4 model calls** and ~**19-22 seconds/query**. The benchmark is primarily QA over finite interactions, ablations single-run on frozen memories, no demonstrated Mission outcomes or privacy/deletion guarantees. Runtime can validate reference/link well-formedness, **not semantic factual correctness, authorization, identity, Claim admissibility, source permissions, influence echo, or model-level forgetting**.

**A.L.I.C.E. existing coverage vs delta.** Existing Raw Evidence/Experience, owner-authorized source-native retrieval, bitemporal XTDB Claim Authority, episodes, multi-graph associative projections, Lifecycle Curator, Retrieval Orchestrator, derived views, and rebuild/rollback already represent the logical capability. New practical evidence is that model-authored **reorganizable** topic representations with *automatically regenerated* access views can remain usable across different Reader models while consulting immutable Source. The source/no-source ablation strengthens the reason not to conflate a summary with evidence. It neither replaces KurrentDB/XTDB/LadybugDB/NebulaGraph/Qdrant nor provides a production-ready source-of-truth layer.

**Governance, upside/risk, action.** A curation edit is a versioned proposal/projection, never a privileged Claim update. Verify provenance scope, source-person/host/assistant-self separation, valid-time vs assertion-time distinction, owner grants, correction and deletion through source, cached views, archives and learned derivatives. Preserve failed edit and rollback receipts. High multi-call cost and uncontrolled semantic regrouping could create omission and evidence promotion. **Future only:** if actual downstream Recollection or curation work exposes source-backed reorganization or stale derived-view failures, examine one case using a staged agent-edited Topic with deterministic view regeneration and canonical Source/Claim checks. Measure observed benefit/cost; do not import the whole Markdown filesystem or reopen graph infrastructure. Do not touch current MFM/N0.

## 2. MixUA — Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction

**Primary:** Yunzhe Wang, Mesut Erhan Unal, Sheng Zhang, Shabnam Ghadar, Peng Tang (AWS Agentic AI/USC), arXiv:2611.10439v1, first submitted **November 7, 2026**, https://arxiv.org/html/2611.10439v1 . **Classification: future challenger primarily for F12 cross-host learning/ecosystem; v1 host/agent/model and multi-device identity isolation remain fully required.**

**Exact method.** Trajectories from many distinct users and agents are split into protected and reusable streams, written by **isolated writers** so private-source writers cannot publish shared entries. Memory entries contain scenario applicability, procedural lesson, original task/pair/outcome provenance and an audience placement among Pair, User, Agent and Global. Separates usefulness/generalization G(e) from confidentiality/disclosure D(e), requiring audience Aud(e) subset of their intersection. Periodic store review can merge/rescope/promote/demote. Pair Reader sees only own Pair + own User + own Agent + Global, typically embedding-retrieved from scoped stores. A learned scope suggestion does NOT replace permission enforcement.

**Evidence/ablations.** CrossLearnBench overlays synthetic identities, preferences, private planted facts and seven coding/office/tool task families across **five users and seven heterogeneous agents**. Main set reported no-memory task pass **72.0%**, Global memory **85.5%**, MixUA LLM writer + review **89.8%**; the authors also report later-round gain of **up to +16.3 percentage points** versus no memory. User preferences retained up to **90%**, versus about **11%** in Global-only memory. On tasks no pair previously attempted, MixUA +**10.1 points** over no memory versus +**5.5** for Global. Planted private-fact forbidden-scope detection up to **0.02%** in the authors' main privacy probes, **but preference leakage in other-user views remains 0.9-4.8% in some settings**: not zero privacy risk. Agents encountered/opened private planted files in **11-26%** of task runs. Controlled variations include with/without store review, memory scopes, writer mode and file-native access; file-native variant had more agent turns (~17 vs ~13.9) and lower preference retention (~75 vs ~90 in reported comparisons), so the system has accuracy/efficiency/privacy tradeoffs. Authors' overall experimental cost approximately **$130K** incl. extensions; four core studies ~$70.3K, heavy memory maintenance and periodic store review. Synthetic five-user privacy distribution, verifier-selected tasks, limited seeds, and no actual federated independent custody/deletion validation limit external validity. Four scope categories are an experimental simplification, **not** a Fable permission ontology ceiling; group/relationship/tenant-specific rules can be richer.

**A.L.I.C.E. existing coverage vs delta.** Already requires host/source-person/assistant-self/relationship identity separation, content authorization, provenance/Claim authority, procedural state, Mission outcomes, model/dataset lineage, independent instance custody, deletion/revocation and multi-device federation. Current Fable v1 is a separate private personal foundation per host, NOT a shared cross-host experience pool; cross-user marketplace/learning after F11 is optional F12. Genuinely new operational candidate is **two orthogonal axes of applicability (user/agent) and disclosure** plus protected/reusable dual-stream distillation and revision of audience placement. Sharing know-how across users may help product growth but creates serious risk if a generalized procedure encodes private identities, sensitive relational information or source-linked influence.

**Governance/risk/action.** Authorize shared artifacts only from independently audited public/reusable evidence; disclosure boundary must be determined and *enforced* by owner-granted rights, not by text from the learned writer. No raw host data, private source-person training, relationship/self history, learned weights or personal provenance to another tenant. Privacy-preserving de-identification by itself is not permission. Any future shared derived lesson needs provenance, source custody, revocation propagation, model-influence lineage, and rollback. **Future only (post-v1 F12):** if cross-user procedural-skill exchange becomes a real authorized product requirement, test one owner-approved general skill and one protected fact/relationship source across heterogenous agents, assert hard egress/access denial and deletion/withdrawal trace. No cross-host memory in current v1, no new storage engine and no cross-product sharing experiment now.
