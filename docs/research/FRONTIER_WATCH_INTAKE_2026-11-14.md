## 1. CoReMem — future Mission/repository experience challenger

**Primary:** *CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation*, arXiv:2611.17316, first posted **November 12, 2026**, https://arxiv.org/html/2611.17316 . **Classification:** **future challenger**, potentially direct capability improvement *only after* an observed cross-Mission code-memory usefulness/effort failure.

**Method and assumptions:** On the ChainSWE setting, the edited repository state persists into the next unknown task. The prior task's memory is written before that task is revealed. Prospective valuation compares matched next-task runs with/without individual preceding trajectory segments to identify useful **WHERE (repository location)** and **VERIFY (executable check)** anchors. An on-policy actor is trained with resolution reward and a cost of successful steps. Additional memory benefit is credited only to steps traceable to memory-supplied anchors, with no-memory and misplaced-memory rollouts as controls. The value is task- and actor-conditional, not an intrinsic truth or authority score.

**Evidence, ablations, limits, expense:** 100 task chains split into disjoint-repository train/test halves, primarily Python/mini-swe-agent. On one 27B actor, resolve rises **21.0% to 25.7%**, steps fall **17%**, cache-aware total tokens **11%**. Across three trained open-weight actors, resolve per total token rises **38–46%**. A frozen model using the anchor memory alone reduces steps on all six evaluated actors. 27B: observed used anchors/1K chars **1.32** versus MemOp **0.92**, ReasoningBank **0.19**, Mem0 **0.14**; misplaced-memory extra steps shrink **+2.1 to +0.3** with provenance-gated reward, while value of appropriate memory rises +1.7 to +2.3 resolve points. Training entails paired agent rollouts, repository executions, on-policy updates, and repeated inference; no energy or wall-time result, no lengthy multi-repo lifelong revision proof, limited language coverage. The paper treats deletable text memory, but trained actors also need proper data/model lineage and unlearning.

**A.L.I.C.E. already covers:** Mission Graph, Experience/Result, source-native code retrieval, procedural memory, Cognitive Workspace, Model Resource Manager and outcome-governed learning. **Genuinely new:** prospective value of *specific next-task reusable action anchors* under a persistent world state, plus **step-local provenance-gated value training**, not just retrieval relevance or retrospective memory-question scores. This is distinct from MemCredit's memory arbitration at a frozen decision state.

**Governance and action:** File/check locations must bind repository revision and action authority; untrusted skill memory cannot authorize tool execution or replace independent test outcomes. Every reference retains source, owner, permissions, changes, revocation and rebuildable lineage. Do nothing now. If a real engineering Mission repeatedly rediscovers earlier work on the *same evolving repository*, try one matched next-task control with a source-linked WHERE/VERIFY memory, including stale-code and denied-access cases. No new generalized training loop now.

## 2. MAPE — evidence preservation and query-routed composition proven modular

**Primary:** *Discovering Effective Agent Memory Designs through Program Evolution*, arXiv:2611.17068, first posted **November 12, 2026**, https://arxiv.org/html/2611.17068 . **Classification:** **future challenger** for Cognitive Recollection composition and cost distribution; not a reason for infrastructure/program-evolution tournaments.

**Method:** MAPE runs an LLM proposer/diagnoser over full Build/Retrieve/Compose programs from small seeds, using a separate frozen evaluation set; one objective values accuracy, another accuracy plus serving cost. Across resulting programs it identifies retaining **raw conversation rounds alongside extracted notes** and **Query-Routed Scaffolding (RQS)**, which applies question-specific extraction, time arithmetic, aggregation/counts and a fixed answerer. Transplants RQS into five independently designed memory systems.

**Evidence/ablations:** LoCoMo selected accuracy-only program **87.94%** (GPT-4.1 mini), cost-sensitive **85.18%** at ~28% of accuracy-only serving cost. LongMemEval selected accuracy-only **77.00%**, cost-sensitive **72.25%** vs RAG **66.00%** (Qwen3-30B-A3B). Across backbones, cost-sensitive LoCoMo program **81.33%**, SimpleMem **69.32%**, at **35%** of SimpleMem's serving cost. Representative RQS/raw-round ablation on Qwen: LoCoMo **75.90**, without raw rounds **63.73**, without RQS **71.46**, without both **63.12**; LongMemEval **77.00/70.50/70.75/63.00** respectively. Query-specific composition transplanted to five baselines improves each. Accuracy-only designs can spend 92% of inference+build calls on construction; cost-aware search moves work to query time. **Limits:** only two QA benchmarks, model-based scoring, one representative design, transfer not always superior to simple RAG, unaccounted search/local CPU/latency, heavy evolution cost, unstable trajectories and risk of benchmark overfitting. A date conversion example shows backbone dependence.

**A.L.I.C.E. already covers:** raw Evidence, source-native reads, analytically derived memory, bitemporal Claims, retrieval orchestration and separate authoritative adjudication. **New transferable idea:** question-intent-specific composition can materially improve retrieval usability **without changing stores**; raw-evidence answer-path ablation is especially clear. But generated computations remain derived and must be reproducible, source-backed, time/identity-qualified and subordinated to Claim Authority.

**Governance and action:** No MAPE program evolution pipeline, benchmark campaign, graph/vector substitution or new memory tier. If a real observed analytic/temporal memory question fails **despite complete retrieved evidence**, try exactly one question-specific compositional repair and verify correct source IDs, temporal Claims, conflict/abstention, revoked-source exclusion and rollback. No current MFM intervention.

## 3. MemInStream — prove a perceptual-memory question actually needs historical memory

**Primary:** *MemInStream: Memorizing or Merely Recognizing? Rethinking Streaming Video Memory Evaluation*, arXiv:2611.15640, first posted **November 11, 2026**, https://arxiv.org/html/2611.15640 . **Classification:** **future challenger** for true long-horizon multimodal/perceptual memory evaluation.

**Method:** Questions are annotated with query times and exact preceding visual evidence intervals. A pair of validation models must answer correctly when original evidence is provided (solvability) and incorrectly when given only text or only post-evidence/recent observations (necessity); contextual tasks additionally require correct prior dialogue+visual evidence and fail when either is substituted. Human reviewers remove inconsistent items. Strict multi-option exact-match avoids tolerant judged free-text scoring.

**Evidence/limits:** **3,799** questions, **8,217** intervals, **17** tasks in four classes; **56.7%** require multiple evidence intervals. Online StreamForest reaches 37.06% state tracking and 37.34% multi-evidence, but only **18.28%** conversational context versus **52.54%** entity-identity binding; hardest multi-hop binding below 24% in highlighted settings. Memory-on JoyAI under matched recent-frame budgets improves state tracking **28.6→43.9%**, episodic retrieval **31.8→41.0%**, multi-evidence **22.3→32.6%**, contextual **26.9→29.7%**. Benchmark creation uses two powerful validation models, human review and historical video; expensive to reproduce and has selection bias towards items those validators agree on. Short video-window timescales, multiple-choice shortcuts, and benchmark-specific video sources do not prove month/year personal continuity or identity governance.

**A.L.I.C.E. already covers:** raw multimodal CAS, episodes, perceptual memory, source-native timed retrieval, host/source-person identity and full cognitive recollection. **Novel test control:** evidence necessity and sufficiency can distinguish *actual historical recollection* from model recognizing recent visible cues or answering from common priors. Not a new perception model.

**Governance and action:** Future-only, use **one** time-stamped consented episode if Fable's native perceptual-memory answer seems correct without consulting earlier evidence. Pair evidence-only, evidence-absent and genuine chronological-stream runs; do not expose later frames, private identities or revoked data. No broad new video benchmark admission.

## 4. HeMeR — conditional serving-efficiency challenger, not a new cognitive store

**Primary:** *HeMeR: Heterogeneous Memory Reconciliation for Embodied Agents via Structured KV Reuse*, arXiv:2611.16487, first posted **November 12, 2026** (subsequent update surfaced November 13), https://arxiv.org/html/2611.16487 . **Classification:** **future challenger**, conditional on measured repeated-context serving bottleneck during dynamic procedural/working memory updates.

**Method:** Track typed declarative/procedural/working-memory chunks and KV ranges. Reconcile only inserted/reordered/changed dependency ranges; mark adapter IDs and recompute incompatible dependencies when rank-8 procedural LoRA switches. Shared-attention LoRA arrangement reduces cross-adapter drift but does not promise arbitrary adapter/KV equivalence.

**Evidence/ablations/cost:** ALFWorld HeMeR **71.43±2.05% success**, **0.18±0.02s/step** versus MemRL **52.86±4.83%**, **0.90±0.04s/step**. Habitat **76.27±3.32%** at 1.82s vs MemRL 61.80% at 2.68s. Real robot table **83.20±4.39%**, **1.87±0.12s** vs MemRL 64.28% / 2.94s; real setting only two tabletop tasks × five repetitions = **10 trials per method**. ALFWorld ablation removing chunk reconciliation reduces success **71.43→59.40%**, cache reuse **75.30→42.75%**, latency **0.18→0.47s**; removing adapter-stable reconciliation gives 64.85% at 0.28s. Additional dependency tracking, KV metadata, adapter-specific recomputation and GPU memory; single-agent and narrow backbone assumptions, no concurrent multi-device validity, no stable provider-neutral API KV guarantee.

**A.L.I.C.E. already covers:** declarative/procedural/working memory, episodic/mission state, replaceable model serving and private hardware-scaled placement. **New:** conditional KV-cache reconciliation across changing memory chunks **and adapter changes**. A cache can carry stale/revoked or mismatched-model content if validity is wrong.

**Governance and action:** Future-only; do not alter the selected serving/model topology. On a measured private-model per-step recomputation bottleneck, test one stable chunk and one corrected/revoked/adapter-changed chunk with mandatory cache invalidation, content hash, permission/identity version and model/adapter lineage checks. No general KV benchmark.

## 5. SkillDuet — screened future model/skill co-evolution, not an MFM fix

**Primary:** *SkillDuet: Co-Evolving Models and Skills through Response Feedback*, arXiv:2611.12109, first posted **November 9, 2026**, newly surfaced in November 14 scan, https://arxiv.org/html/2611.12109 . **Classification:** **future challenger**, closely related to existing ENGRAM, Anchor, FGSE and capability-formation findings (no independent current action).

**Method/evidence:** On-policy distillation uses Local procedural skills from paired successful/failed executions to teach weights; selected Local skills periodically consolidated into Global persistent skills. Retention scores use **response-shift magnitude** rather than semantic similarity. Qwen3-4B: ALFWorld **98.57%** vs matched SEED-API **95.71%**, WebShop **92.97%** vs **87.50%**. WebShop ablation: random global selection **89.06%**, response-shift-ranked **92.97%**, Local-only **87.50%**. ALFWorld historical candidate scoring showed magnitude better than task-reward weighting; authors explicitly note magnitude is **not proof** of future causal utility. Experimental Top50% was best among 25/50/75% tested, not a universal retention ceiling. Cost: 300-step WebShop run **37.09h**, **35,036** Local HTTP calls, **145** Global API calls plus model scoring; not a cheap Fable local-v1 recipe. Incomplete support for real permission-bound personal histories, deletion/unlearning, enduring capability and cross-host isolation.

**A.L.I.C.E. already covers:** procedural/parametric/external memory, MRM, lineage, outcome-gated personal learning and rollback. **New candidate:** regularly remeasure the external-skill value **as the underlying model changes**, instead of assuming a skill helpful to an earlier checkpoint remains helpful. Response shift is a candidate signal only, never permission or authority; requires actual verified outcomes and post-deletion influence checks. Revisit only when native personal learning already works and retained guidance is observed becoming redundant or harmful.
