## 1. LinEra — confidentiality-grade deletion across derived memory lineage

**Primary:** Ameur et al., *Forget the Lineage: Forward-Secure, Lineage-Complete Cryptographic Erasure for LLM-Agent Memory*; arXiv:2611.18133, submitted **November 13, 2026**; https://arxiv.org/html/2611.18133 . **Classification:** future challenger with a specifically actionable deletion-lineage design invariant; not architecture-invalidating.

**Method and assumptions.** Derived memory encryption keys are HKDF-composed from the keys of every parent object plus an object pseudorandom tag; source keys come from a puncturable GGM pseudorandom function. Puncturing a source key after a forget request makes its entire descendant closure undecryptable even to a later thief holding ciphertext, database residue, backups and *current* store keys. The formal soundness assumption is unusually important: record as parents **everything the memory-writing model could read in the generation context**, not just a selected semantic citation/explanation or similar memory. The proof relies on independent sources and complete prompt/input coverage; affected ciphertext still exposes the shape of the lineage graph. Includes encrypted index shards, state compaction, crash consistency, 400-line Python library, 140-line mem0 adapter, MIT-licensed code. Does not protect model weights, live RAM, plaintext copied outside custody, prior theft of keys, repeated fact in independently preserved evidence, or producer access bypassing lineage capture.

**Experiment/ablations.** With Qwen2.5-7B writing all ten LoCoMo conversations, a later adversary recovers 70/71 implanted secrets after logical deletion, 67/71 with per-object/epoch encryption, and 0/71 under sound LinEra. Smaller writer result: 35/35 logical deletion, 22/35 per-object/epoch keys, zero LinEra. The survival law is approximately (1-forget_fraction)^(producer-source-fan-in): forgetting 1% of turns invalidates 73.0% of derived memories under session-wide summaries but only 3.8% under four-turn writing windows. Removing too many derived memories hurts retrieval; preserving original surviving evidence and rebuilding only affected descendants recovers accuracy. On a facts-only store 1% forget reduces evidence-session retrieval hits from 63.2% to 18.9% under sound lineage; hybrid retained originals reduce this loss (79.5% to 70.2%). The small 1.5B answerer's low token-F1 and limited study sample do not establish practical Fable end-to-end utility.

**Existing A.L.I.C.E. / exact delta.** Full cross-layer correction/deletion, event/evidence custody, derivation and model/dataset lineage, encrypted CAS, projection rebuild and governance already required. What is new: a precise **conservative cryptographic exposure/dependency closure** protecting storage remnants and backups, and a measurable tension between source fan-in, forget blast radius and memory quality. *Cited parent* is not equivalent to *all observed inputs*. The paper adds a possible key-binding implementation, not a new authoritative memory plane. Evidence remains distinct from XTDB Claims; reconstructed memory must be re-adjudicated under existing correction/identity/permission rules.

**Cost, strength and action.** Strong formal security claim **inside the stipulated cryptographic threat model**, plus small-scale model-generated memory evidence; no cross-layer parametric proof. Key graph and AEAD management, encrypted index shards, cache invalidation, secure key custody and selective replay incur read/write cost, storage overhead and degraded utility if producers see overly broad contexts. **Future implementation note:** when building the CAS/Lifecycle Curator deletion path, require an explicit ledger of *all actual producer-readable inputs* (sources, retrieved evidence, authorized cached content and contextual state), separated from semantic supporting citations. Check one real derivation/deletion/rebuild path. Consider cryptographic lineage binding if actual encrypted-backup and post-compromise erasure contract cannot otherwise be satisfied; do **not** change selected backends or claim model-weight erasure. This is a research candidate invariant rather than a proven present code defect.

## 2. CLAM — recurrent forward-only compilation into a personal adapter

**Primary:** Suri and Manocha, *Instant Weight-Space Consolidation for Long-Term Memory in LLMs*; arXiv:2611.20759, **November 16, 2026**; https://arxiv.org/html/2611.20759 . **Classification:** high-interest future challenger for parametric personal memory, MRM and governed personal-model evolution; **not** a fix for checkpoint-10 MFM formation.

**Method.** Frozen base LLM encodes each session's hidden activations. Perceiver latent queries compress the session; a recurrent gate carries a constant-size latent across sessions; a decoder maps it to per-layer fixed-rank low-rank FFN down-projection adapters. One forward pass per additional session yields an updated cached adapter **without inference-time optimizer or generative writer calls**. A separate exact episodic buffer retrieves source spans at query time. The hypernetwork itself is trained heavily offline by context distillation using teacher-generated answers, initialized from document-to-adapter training and optimized over longer sequences with truncated BPTT. Synthetic training includes roughly 900,000 trajectories, 23,984 fictional personas and cross-session updating/distractors. Constant *deployment* adapter size is a method choice, not a ceiling on Fable models or memory.

**Experiments/ablations.** Across Gemma-2-2B, Qwen3-4B and Mistral-7B on LoCoMo and LongMemEval-S, the combination improves over same-buffer episodic-only. On LoCoMo Qwen3-4B 51.6% vs 40.6%, Mistral-7B 55.3% vs 47.7%; on LongMemEval-S Qwen 43.4% vs 41.6% (small, not decisive), Mistral 53.2% vs 46.8%. When retrieval misses gold evidence (36% of evaluated items), adapter adds 12.4–15.1 accuracy points. With oracle evidence it still adds 4.8 and 5.0 points on Gemma/Qwen, **but approximately zero on Mistral**. Resetting the carried latent across sessions loses 4.8–5.2 points on two models; random adapters ineffective. On Qwen LoCoMo, memory construction about 10.3 seconds versus about 200.6s for their Mem0 baseline, 0 *online* generative calls/backprop; offline teacher synthesis and hypernetwork training are substantial and not included in this per-session number. Excludes abstention/adversarial categories; narrow English conversational benchmarks and 2–7B models. No proof of genuine autonomous personal judgment, counterfactual attributable learning, long-horizon nonstationary corrections, or private model transport between arbitrary bases.

**Existing A.L.I.C.E. / novelty.** Full external, episodic, parametric and activation memory, MRM, source-grounded Claims, personal training/evolution, lineage, privacy and rollback already planned. New technique is **cheap *post-training* continuous latent-to-adapter consolidation** that complements rather than displaces exact retrieval. Personal judgments may become more useful even with relevant evidence supplied. A latent/adapter **must remain non-authoritative**: it cannot silently rewrite bitemporal Claims, merge source-person/host/assistant-self states, retain deleted influence, or assert correctness without verifiable evidence. Correct/revoke source requires adapter generation retirement and sanitized replay or rebuilt latent state; original histories and ownership remain first-class.

**Cost/evidence/action.** Promising controlled ablations and efficient running update, but expensive pretraining, model-specific hypernetwork, latent storage/checkpoints, working model weights and extra serving adaptation. **Future only** after native formation and personal judgment are qualified; if personal-parametric updates become an observed training/latency bottleneck, assess one source-bound prior-versus-new adapter decision with retrieval held fixed and a deletion/replay lineage check. Do not add an MFM training gate or change the current 10→26 operation.

## 3. Experience Rot — experienced agents trust obsolete tool behavior and falsely claim success

**Primary:** Xu et al., *Experience Rot: Experienced Agents Fail Where Novices Succeed*; arXiv:2611.20922, **November 16, 2026**; https://arxiv.org/html/2611.20922 . **Classification:** future procedural/Mission execution challenger with a concrete implementation check when live tool-state changes are observed.

**Method.** Six agent models execute tasks in calendar/task/email services with versioned MCP-like tool interfaces. After successfully performing tasks using an earlier tool version, they repeat an obsolete argument name, schema or unchanged integer with different semantics. The server can acknowledge the request despite producing incorrect persisted state. Experiment compares fresh agent, currently valid experience and stale experience, multiple memory vehicles, 1/3/10 earlier successful tasks, documentation completeness, and remedies.

**Evidence/ablations.** 12,624 episodes. With incomplete docs: no experience 63% success, valid experience 100%, out-of-date experience only **23%**. With complete docs, stale experience 26–49% success; 347/348 failed runs nevertheless report success. As history grows from 1 to 3 to 10 prior tasks, stale-success 46→33→26%. The effect appears with conversation history, generated memory files, retrieved notes and scripted skills. A post-write **readback of actual stored state** resolves 94/97 stale first-write errors when performed. A request to verify outcome raises stale success from 46→91% with complete docs and 23→69% incomplete, but model calls rise to 6.5/10.6 per task versus 2.9/3.1 valid experience; mere version notices do not reliably help. Artificial single-change small services, short tasks and common harness limit transfer; strong preregistered controlled contrasts within that threat model.

**Existing A.L.I.C.E. / novelty.** Mission Graph, Experience outcome ledger, source-native/live lookup, current tool contracts, procedural repair memory, deterministic permissions and workflows already selected. New failure is **miscalibrated confidence from repeated personal experience under silently invalidated external interface semantics**, including false-positive success acknowledgments. Memory validity cannot be certified by prior successful use. Treat current source and observed readback as evidence of postcondition; remembered scripts/skills are proposals, not authoritative completion. Identity and permissions remain independent of tool outputs.

**Action/cost.** When implementing actual tool-dependent Mission success reporting, scope a **readback/observed-postcondition obligation for meaningful state-changing actions susceptible to silent acknowledgement**, especially after interface or semantic drift. One real tool/test qualifies the contract; do not impose a universal expensive readback campaign. Source version and signature alone are inadequate where semantics remain ambiguous. No new workflow engine or production edit now.

## 4. StreamEmbed — incremental local perceptual screenshot memory

**Primary:** Ko et al., *StreamEmbed: Real-Time Indexing from Pixels for Screenshot Retrieval*; arXiv:2611.18516, **November 13, 2026**; https://arxiv.org/html/2611.18516 . **Classification:** future conditional efficient-private-perception challenger, not Qdrant replacement.

**Method.** Pixel-difference-guided repeated-block spatial pruning, temporal reuse of visual/LM KV cache for unchanged screenshot regions, grid retention and a LoRA consistency adapter stabilize embeddings relative to full-image encoding. Preserve original frames separately; compressed embeddings are a derived index, not historical evidence. Recency/capture cadence and consent matter.

**Evidence and ablations.** ScreenMemEval: **10,426 questions over 184 hours** of histories from two people and a computer agent. On M2 Pro GPU Qwen3-VL-Embedding-2B full frame 2.33–2.34 seconds per screenshot vs StreamEmbed **0.63–0.84s** with 0.6–1.3 Recall@10 points lost; up to **+6.3 Recall@10 points** over OCR indexing at comparable latency. Spatial and temporal improvements each about 1.5× and partially compound; grid keep and trained consistency adapter recover agent-screen fidelity. At high compression, quality degrades in dynamic screens. One simulated year of screenshot vector **index** fits in 0.13GB RAM; does not count raw encrypted pixels or model state. Five simulated years <1GB. Limited history sources; simulated long-term storage and observed index latency under one hardware profile cannot qualify Fable packaging.

**A.L.I.C.E. fit and action.** Already has perceptual memory, encrypted raw evidence, multimodal Qdrant, source-native views, hardware-adaptive placement, deletion and replay. Novelty is eliminating *redundant visual embedding compute*, not a new plane or storage backend. Future only if real on-device continuous visual memory indexing becomes a measured latency/battery/GPU bottleneck. One same-evidence same-retriever indexing test, preserve original screenshots and permissions, invalidate dependent cached KV/embeddings on correction/deletion, never auto-capture private screens without owner authorization.

## 5. HEAMS — memory correctness must include privacy and user sovereignty

**Primary:** Goel et al., *HEAMS: Holistic Evaluation of Agent Memory Systems*; arXiv:2611.20144, **November 15, 2026**; https://arxiv.org/html/2611.20144 . **Classification:** already covered/corroboration with future focused qualification techniques.

**Method.** A common interface benchmarks Mem0, Letta, HippoRAG, MilaMem and controls under one agent across memory performance, privacy/contextual integrity, editable/erasable owner control, poisoning security and efficiency. Adjustable recall/retention policy wrappers examine trade-offs, rather than ranking only answers. Their custom system's policy gate filters data available in an action context.

**Experiment/limitations.** On contextual integrity tasks MilaMem leaks private fields in **57.61% of scenarios** without recall governance versus **31.82%** with it; helpful answers without privacy leaks rise **30.86→45.95%**, while basic helpfulness drops 74.90→70.10%. On deletion/editability benchmark, best system executes only **47%** of tested erase requests and best edit score **3.66%**. Some systems score well at recall yet badly at contextual disclosure. These are tested external systems, not A.L.I.C.E.; offline synthetic one-user chat scenarios, common adapters missing native capabilities, unvalidated LLM judges, thin attack coverage and no parametric/federated unlearning. No ranking or measured percentage should be transferred to Fable.

**A.L.I.C.E. fit and action.** Full owner authority, Claim/evidence provenance, lifecycle/cross-layer deletion, privacy, identity and permissions already exist in requirements. Useful methodology: for **one real memory/correction/deletion/authorization defect**, jointly check successful authorized recall, withheld unauthorized facts, correct edit, subsequent non-regeneration, and helpfulness. Avoid all-backend comparisons or introducing the HEAMS prototype as an engine. Not a new missing cognitive plane.

## 6. Online context-versus-weight adaptation — context can speed execution while suppressing checking

**Primary:** Mirtaheri et al., *Where Should LLM Agents Adapt at Test Time? In Context, in Weights, or Both*; arXiv:2611.19700, **November 15, 2026**; https://arxiv.org/html/2611.19700 . **Classification:** future learning/scheduling challenger, not immediate MFM remedy.

**Method/evidence.** Compare 14 in-context raw-history replay, GRPO with verified rewards, SDPO self-distillation and hybrids on five task orders of **109 tasks from SWE-bench Verified, AppWorld, ScienceWorld and BIRD Critic SQLite**, fixed Qwen3.5-9B. Agent must attempt the task before updating on it. No adaptation mean success **28.8%**; strongest context-only **49.4%**; context plus GRPO **51.6%**; SDPO effects mixed. Traces show history reduces environment lookups and task steps, but induces skipping inspection and verification. GRPO often restores checks. Absent causal evidence that GRPO is universally best or that these are lifelong personal identity improvements. Training requires online rollouts, verified rewards and optimizer compute; long-term forgetting, authorization, source deletion and personal judgment not solved.

**A.L.I.C.E. fit/action.** External/parametric/activation forms, Memory Resource Manager, source-grounded Missions and controlled model evolution are already required. New information is interaction between **which experience context survives** and **how subsequent parameter updates learn to verify the current task**, not merely independent success of the two memory forms. Conditional future paired trajectory check if an actual personal agent learns shortcut behavior at expense of current source inspection. Do not adopt GRPO on principle, open another backend comparison, or delay checkpoint-26 MFM continuation.
