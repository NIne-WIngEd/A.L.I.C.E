## 1. HabitusMem — request-conditioned, evidence/scope/status-aware belief projection

**Primary:** Lu et al., *HabitusMem: Belief Memory over Evolving User Preferences for LLM Agents*, arXiv:2611.25855v1, first submitted **November 19, 2026**, https://arxiv.org/html/2611.25855 . **Classification:** **future challenger** to MFM read-time/context formation, host-model projection and Cognitive Recollection. It does **not** supersede bitemporal Claim Authority.

**Method/assumptions:** A trained Qwen3.5-9B/LoRA writer reads selected raw history plus **the current request** and outputs one text belief per record: `claim | evidence | scope | status`. Status distinguishes active, superseded and retracted, with 'do not use' not necessarily implying the underlying observation is false. It learns direct belief writing, incremental update, request projection and exact action-constraint projection from 40,766 weighted training examples (18,529 direct; 6,270 updates; 6,379 request; 3,196 action repeated three times), with teacher-generated derived examples. Its Bayesian belief equations are motivational, **not implemented numerical filtering**. Importantly, the writer rebuilds request-specific output from a bounded history view each time, without retaining its own canonical state between requests; that makes this an evidence-conditioned *read-time projection*, not an authority replacement.

**Experiments and ablations:** On PersonaMem-v2 English 32k/5,000 queries, compact-memory accuracy is **0.537 / 0.484** under Qwen3.5-397B-A17B / DeepSeek-V4-Flash, versus strongest compact alternatives **0.489 / 0.438**. **Full raw history does better on this metric** (**0.569 / 0.527**), despite the paper's best compact-memory claim. On VitaBench 2.0 (771 subtasks, 56 people, four trials each), mean reward with the two agents is **0.3291 / 0.3573** (full history **0.3382 / 0.3119**); all-four-trial pass is **0.1310 / 0.1284** (full history **0.1297 / 0.1102**). Wrong/missing query intervention degrades QA accuracy from **.537/.484 to roughly .40/.34**, confirming that **learned request conditioning**, not a generic schema prompt, drives most QA benefit. Aux-task and field ablations are mixed in tool use; a schema-free control has better all-four success than complete HabitusMem in some agent settings. Evidence is stronger for *in-context personalized decisions* than native evolving personal judgment.

**Existing vs genuine delta:** A.L.I.C.E. already requires canonical observations, host/relationship/assistant-self separation, bitemporal valid-time Claims, MFM evidence-citing proposals, exact-source retrieval, a Recollection orchestrator and governance. New implementation option: train a **read-time, query-specific personal-belief projection** with explicit provenance, situational scope, retracted-use state and exact action constraints, rather than expecting the downstream feature model to infer current applicability. A model-generated belief remains a derived hypothesis and cannot update a canonical Claim or change owner consent by itself.

**Governance/cost/limitations/action:** Cost is a 9B writer inference per new history+query (cache identical requests), LoRA training on tens of thousands of examples, source-read tokens and state generation; full history remains accessible, not copied wholesale into third-party prompts. Fixed history selection can omit decisive older evidence; retractions and exact tool constraints remain error-prone; broader email/scheduling and real long-life host studies absent. Preserve source ID, effective time, speaker, relationship vs host scope, permission checks, revocation, rollback and post-deletion invalidation in read caches. **Action:** only if a real host-preference misapplication occurs, compare an authorized request-conditioned belief projection against the existing deterministic Claim/retrieval path on that case. Do not alter current MFM recipe or adopt generated beliefs as authoritative.

## 2. IBM self-distilled memory deployment lessons — the *model* determines memory dose

**Primary:** Jayaram et al., *How Much Should an Agent Remember? Deployment Lessons from Self-Distilled Memory for LLM Agents*, arXiv:2611.26361v1, first submitted **November 19, 2026**, https://arxiv.org/html/2611.26361 . **Classification:** **already covered/corroboration** for Experience-based procedural memory, with a **future challenger** in capability-conditioned retrieval/dose policy and a useful concrete preservation invariant.

**Method:** Logs -> 1–3 verified-outcome-backed lessons per trajectory -> deduplicated consolidated guidelines -> all- or subset-delivery. Each guideline tracks contributing lessons, support count, source-task and success/failure polarity. A key invariant is **sum of independent source lesson supports equals sum of consolidated supports**, with unchanged carry-through of unmatched lessons. This is not equivalent to truth/authority: high-support advice can be systematically wrong. The IBM team's deployed `altk-evolve` library interfaces with CUGA and watsonx Orchestrate. The paper discusses real implementation bugs: silently dropped provenance fields, source-index double counting, swallowed HTTP errors and completely inactive memory writes yielding plausible logs.

**Evidence/ablations:** On AppWorld normal, DeepSeek-V3.2 task completion **79.8% without memory -> 89.3% with all 191 guidelines**; scenario completion **64.3 -> 80.4**. The complete set consumes ~**263k vs 148k** tokens/task (+78%); 47 high-support guidelines yield ~+5.9pp task completion with +27% tokens. Aggressively summarizing to twelve guidelines yields only **+2.9pp** task completion, compared with **+9.5pp** full long tail. For less capable gpt-oss-120b, task completion **39.9% -> 51.2% all 199 -> 55.4% with ~29 selected guidelines**; selected cost ~**116k vs 110k** baseline tokens/task, versus 166k all. One high-support pagination rule produced a new failure until manually repaired, refuting support=count correctness. Identical runs flip dozens of individual task outcomes; small differences (<~5 tasks on 168) are noise. Against ACE, model/harness baselines differed; matched improvement is much closer than unadjusted headline comparison. Product CUGA GPT4.1 improvement on AppWorld is small **71.03 -> 72.42%**, not statistically decisive. Configurations were partly chosen on test_normal after dev was used for memory mining: risk of test selection bias. These details restrict claimed portability.

**Existing vs genuine delta:** Fable already preserves individual experiences, stable evidence identity, procedural lessons, MRM and selective contextual memory. New operational evidence: **memory quantity must be conditioned on the *serving model's ability to use it***, and consolidation must preserve the multiplicity, provenance, trigger and version/status required by downstream selection. This is *not* a fixed-size cap or smaller product tier, and no new storage engine is indicated. Observation that a rule recurs never establishes its validity.

**Governance/cost/action:** Store independent source lesson IDs and source outcome/evaluator receipt, keep contradiction/staleness/repair status, enforce per-host isolation, permissions, deletion/revocation through derivative guidelines, and rollback of bad guidance. Monitoring write-path progress and surfacing transport/model errors is valuable but **the paper does not show an existing ALICE code defect**. **Action:** at the next actual Lifecycle Curator / procedural consolidation implementation, preserve support-lineage count and source-task identifiers as invariants of that real feature. For a demonstrated model-specific context-cost/accuracy regression, compare current selective delivery with a bounded alternative on same agent/scaffold; no broad backend/benchmark campaign now.

## 3. EvoMem — temporal evidence-state-controlled multimodal recollection

**Primary:** Guan et al., *EvoMem: Self-Evolving Skills for Time-Aware Long Video Memory Agents*, arXiv:2611.25889v1, first submitted **November 19, 2026**, https://arxiv.org/html/2611.25889 . **Classification:** **future challenger** for perceptual/autobiographical memory and query-conditioned Recollection.

**Method:** Construct three aligned, derived memories: multi-resolution temporal-graph subject/relation/object edges with explicit video time spans, interval-level text and visual frame evidence. Retrieval iteratively uses the evidence already found to set/narrow/shift/expand its next temporal range. A procedural *retrieval skill* specifies targets, modality, retrieval path and stopping. Skill revisions proposed from successful/failed traces are only admitted when validation answer-correctness transitions improve, without model-weight updates.

**Experiments/ablations:** Four long-video QA benchmarks: EgoLifeQA **55.0%**, Ego-R1 **61.0%**, LVBench **59.1%**, Video-MME(L) **65.2%** (reported mean **60.1%**). Component ablation: remove time-aware search **53.0%** mean, basic time-aware operations **57.6%**, human-crafted retrieval skills **58.6%**, evolved skills **60.1%**. Frozen skills generalize across test-time retrieval backbones on Ego-R1: Qwen3-VL-8B **50.3->51.7**, 32B **58.7->61.0**, GPT-5.5 **66.3->72.3**. Their benchmark scoring is QA-focused, not real lifelong person identification or Mission success; online evolving skills need validation feedback, and preprocessing long video with multiple modalities and retrieval turns costs storage/model calls.

**A.L.I.C.E. impact:** Already has raw audiovisual Evidence, Episodes, temporal/multi-graph and exact visual source reads, Qdrant vectors, MRM and procedural learning; novel candidate is **using each retrieved temporal clue as a binding constraint on subsequent time-range and modality access**, combined with governed retrieval-skill admission. Graph is derived, not Claim Authority. Preserve authorization over raw media, timestamps and entity separation; revocation must invalidate visual index, temporal graph, learned skill traces and caches; source time intervals must remain reconstructable. **Action:** future-only focused trial if genuine repeated-similar-event / mislocalized historical-video evidence appears, not a new multimodal database or benchmark now.

## 4. CoLiR — contrastive likelihood replay of previously improved behaviors

**Primary:** Gao et al., *Policy Improvement-Guided Replay for Continual Reinforcement Learning*, arXiv:2611.25989v1, first submitted **November 19, 2026**, https://arxiv.org/html/2611.25989 . **Classification:** **future challenger** for governed native personal-model evolution and performance retention. No current MFM root-cause repair.

**Method/assumptions:** In sequential RLVR, score historical prompts by rise in log-likelihood for **final-policy correct** responses plus fall in likelihood for **initial-policy incorrect** responses. Uses already generated rollouts plus cross-policy likelihood scoring, no extra response generation for replay *selection*. Stores at most **80 prompts per historical task**; replays 4 or 8 of 32 batch prompts in later GSPO RL, with local KL weight 0.01 on replay only. Theory via one-step performance-difference lemma and ideal KL-regulated policy is motivational, not guarantee of continual safe real-world decisions.

**Evidence:** Re-evaluates corrected MRCL across sequential MedBookVQA, Navigation, We-Math2, Puzzle, FinMME with Qwen3-VL **2B/4B/8B**; highest mean final and task-averaged accuracy in evaluated comparators; final-accuracy advantage over CPO reaches **+9.99 percentage points at 8B**. Ablations compare historical selection with random/other scores and replay components; results are verified-answer tasks, not host-specific value or preference evolution. OOD retention measured but not an individual lifelong identity experiment. Cost: score cached rollout likelihoods, retain source data, repeated RL rollout/replay training and checkpoint lineage.

**A.L.I.C.E. impact/governance/action:** Existing model/dataset lineage, personal adapters, archived experiences, governed promotion and rollback provide logical coverage. New candidate is **replay selection based on demonstrated policy improvement rather than similarity or raw uncertainty**. Historical prompts, frozen policies and rewards may be contaminated by revoked personal data; delete/rebuild affected sources and derivative adapters or block replay. Current MFM's 0/9 native formation is a *formation* defect, not historical post-RL forgetting. **Action:** only after real personal-model learning works and an observed sequential-training capability regression exists; compare this targeted replay policy against the incumbent on the same governed failure. Do not launch RL experiments to validate the paper alone.

## 5. Delegation security — source-bound, attributable execution across untrusted agents

**Primary:** *Attacks and Defenses in Decentralized Multi-Agent Systems with Hop-by-Hop Task Decomposition and Delegation*, arXiv:2611.25056v1, first submitted **November 18, 2026**, newly surfaced in this intake, https://arxiv.org/html/2611.25056 . **Classification:** **future challenger / corroboration** for externally delegated Missions and federation trust; not a current multi-device transport blocker.

**Method/evidence:** Threat model lets one malicious/compromised independently administered agent alter delegation/output/delay or solicit private memory. Tested attacks yield up to **100% task failure**, **7.7x** tokens, **3.2x** runtime, and exfiltration of up to **94%** relevant prior tasks. A cryptographically attributable verified-execution/delegation trace plus LLM auditor detects/attributes **98%** tested attacks on HiddenBench; comparing auditor prompts, crafted audit has **96%** mean recall against **64%** adapted audit baseline on an attack subset. A cryptographically signed trace establishes *who did what*, not that their plan was correct or that data disclosure was authorized. Assumptions restrict collusion, underlying weights and infrastructure attacks; evaluations are controlled and overhead for audit itself must be considered.

**Existing/delta/governance/action:** A.L.I.C.E. already requires owner-authorized tool/agent capabilities, Mission/Experience trace provenance, relationship/agent identities and permission-aware federation. Novel threat evidence is **delegation-chain accountability across independently administered peers**, rather than NATS JetStream device buffering alone. Every delegated action needs scoped consent, immutable/verifiable causality and bounded egress; never send host memories to unknown peers by default. Preserve revocation and trace retention under authorized deletion, and make audit artifacts independently reconstructable. **Action:** only when a real external peer-delegation flow is implemented, use a focused hostile-peer delegation/egress case to protect the permission contract; no change to Temporal/NATS or current native learning path. Cross-user ecosystem sharing remains F12.

## 6. HOPD — sparse historical multimodal replay from archived adapter teachers

**Primary:** Li et al., *Historical On-Policy Distillation for SAR MLLM Continual Learning*, arXiv:2611.25391v1, first submitted **November 19, 2026**, https://arxiv.org/html/2611.25391 . **Classification:** **future challenger**, narrow parametric-perceptual continual-learning setting.

**Method:** After learning each source distribution, archive its LoRA state as teacher; distill those teachers on **current evolving student's generated prefixes** using sparse old images with augmented views preserving coordinates, consolidate into **one deployed adapter**; no source ID at inference. Retention is source-conditioned training, not canonical personal memory.

**Evidence/cost:** Nine SAR remote-sensing sources with seven shared tasks; Qwen3.5-4B, rank-8 LoRA **19.5M trainable params**, 356,624 train QA, 5,988 eval QA, 3 source orders; one retained old image plus seven QA/source. Final mean **54.51** vs next-best MR-LoRA **51.55** and replay-SFT **47.06**; lowest reported backward transfer degradation **18.58**. Sparse-history comparisons show one-image HOPD ~four-image replay-SFT. Requires historical teacher-adapter archive growing with source count and additional teacher inference and continual updates; SAR/VQA-only findings cannot establish personal-value/identity retention. A prior checkpoint contaminated by deleted data remains an invalid teacher even when labeled historical. Existing Fable model/adapter lineage and source-aware privacy contracts cover the plane. **Action:** future-only if personal perceptual adapter training has measured source-shift forgetting and retained training examples are scarce; respect model deletion/rollback. Not a new Fable model-count ceiling or current MFM change.
