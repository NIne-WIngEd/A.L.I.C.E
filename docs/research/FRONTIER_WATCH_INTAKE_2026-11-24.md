## 1. WASP — recurrent generation of host-specific weight updates

Primary: Xie et al., WASP: Continual Weight Adaptation for Streaming LLM Personalization, arXiv:2611.30134v1, submitted 23 November 2026. https://arxiv.org/html/2611.30134

Classification: **future challenger** for MRM, host-model parametric adaptation, FBM training. Related to November 17 CLAM; new evidence is explicit preference revision/retention and surprise-triggered updates, not the generic hypernetwork concept.

Method: frozen task-adapted backbone, inter-layer latent tokens conditioned on user-history hidden states, per-module LoRA factor decoders. End-to-end hypernetwork training with downstream loss and penalty when personalized loss exceeds base loss. Learned recurrent mixing combines initial structural tokens and previous latent state with new interactions. Trigger regeneration using accumulated relative response loss; batch pending interactions until threshold. No per-user backprop at update time, but relies on observable query/response pairs and task-trained shared generator.

Evidence: OOD LaMP/LongLaMP classification accuracy .702 vs full history .621 and SHINE .608; generation ROUGE-1 .369 vs SHINE .379 (not uniformly better). Temporal Amazon23 ROUGE-1 .3357 vs static WASP .3292; AbsGen .4052 vs .4013. Semi-synthetic two-chunk MovieLens explicit revision 1.000, retention .997; static adapter revision .010, retention .993. This is a controlled genre preference experiment, not arbitrary personal change. Lower surprise threshold .25 vs 1 improves all four averaged generation metrics slightly; inter-layer-only attention gives .722 average classification vs .709 intra-full and .6905 intra-rank. At 20k tokens P2P ~3.5x and per-user fine-tune >100x update FLOPs relative to WASP; reported 8.7 MB/user state and 2.2 GB additional peak serving memory. Shared training uses 32 H20 GPUs, inference experiments 8 RTX PRO 6000 Blackwell GPUs; no measured laptop end-to-end qualification. Fixed-size claim applies to learned state, not original evidence custody; pending chunk size matters. Evidence moderate for tested personalization, low for lifelong identity/judgment/deletion.

Already vs new: Fable specifies separate host state and parametric/activation/external memory, governed model evolution and role-specific decisions. WASP is a potential lower-cost way to adapt a host model and detect when updates are worthwhile, NOT a personal foundation or source authority. Preserve the host vs source-person vs self vs relationship distinction; user response loss cannot independently establish truth, consent or valid-time change. Recurrent state and generated adapters need source-generation lineage, correction/revocation invalidation, authorized replay/rebuild, rollback and influence-echo testing; never discard original records for fixed-size state. Shared training cannot ingest private host histories without authorization.

Action: future only; if established host-model adaptation has a measured update-cost or revision/retention defect, compare one bounded recurrent-update candidate with current method on real authorized preference changes and irrelevant controls. No change to MFM/N0 or release gates.

## 2. RoboLiveMem — separate stale action commitment from missing historical memory

Primary: Zhang et al., RoboLiveMem: Is Robot Memory Solved When the World Does Not Wait?, arXiv:2611.30047v1, 23 November 2026. https://arxiv.org/html/2611.30047

Classification: **future challenger** for live source-native reads, world/perceptual memory, Mission execution freshness; complementary to Experience Rot (changed tool contracts) and EgoWitness (historical observer/object identity).

Method: same seeds under paused and running world clocks, with event/decoy/null variants and a live visible twin exposing decisive state. Separate paused-minus-visible (execution) and visible-minus-hidden (memory) gaps. A pre-command commit check reobserves target and cancels/replans if changed. Fixed-clock intervention and offline frame probe isolate latency vs observation gap; privileged scripted policy establishes solvability.

Evidence: 29 task families, 16 models, 34,176 episodes across BEHAVIOR-1K, MuJoCo and ManiSkill. In realistic change episodes eight commercial models average 97% paused vs 50% live. On commit-check-eligible realistic subset Opus 61.5→97.1% hidden live, Astra 80.8→95.2%; not directly comparable with overall average. Controlled repeated swaps still show hidden 80% vs visible 95% for Opus after check; several models degrade with the check. On swaps the strongest models retain 15–31 pp memory gaps despite observation refresh. Evidence moderate for controlled causal localization, low for actual autonomous deployments; simulated scenes, harness differences between model families, some cue/task differences, no real physical safety proof. Runtime costs one additional observation plus conditional replanning, repeated tracking/identity processing and retaining authorized observations.

Already/new: existing live reads, temporal Claims, Mission Graph and source-grounded identity support this. New diagnostic separates stale commitment during deliberation from failed temporal identity tracking; refreshing current state cannot recover hidden history. No blanket re-verification loop. Observation time, source version, subject/object identity and permissions must survive plan binding; new observations do not overwrite evidence history. Revoked observations and derived caches must invalidate affected plans, replay/rollback preserves lineage; external actions cannot be undone by code rollback.

Action: future only, on a real mutable-world or software task that acts on stale state, test a single pre-commit version/reobservation control, and if hidden history remains necessary, localize that separately. Do not change Temporal or graph engines. Paper's license CC BY-NC-SA; evaluate artifacts separately before product use.

## 3. Can Search Agents Correct Their Own Errors? — isolate retrieval, delivery, revision and completion

Primary: Pagadala et al., arXiv:2611.30243v1, 23 November 2026. https://arxiv.org/html/2611.30243v1

Classification: **future challenger** for Recollection and epistemic correction, with diagnostic relevance to source-grounded judgment. Builds beyond previously tracked causal citation provenance and CompAct-Bench; no proven MFM repair.

Method: BrowseComp-Plus fixed corpus (~100k docs), replay each model's own wrong closed-book answer, vary prior speaker/wording and evidence availability; separate search result depth, gold-first placement, direct neutral vs decisive passage delivery, and curated answering. Measure correct/repeated prior/other wrong/abstention/no parsable answer, not just retrieval recall.

Evidence: 709 questions, 26,665 supplied-evidence conditions, four open-weight checkpoints. Nemotron confident prior reduces paired accuracy 16.1 pp even with answer-bearing text; insisting user condition changes both wording and speaker and loses 32.9 pp (gpt-oss 12.6 pp). Decisive vs neutral delivery improves Qwen3.5 51 pp and Nemotron 22.4 pp, small selected intervention cohorts. Gold-first placement still often fails to open decisive source. Nemotron 19/51 decisive-delivery episodes exhaust search budget without an answer; when parsable, 21/26 correct. Curated direct answer same model/questions ~89%. Parser formatting sensitivity reduces but does not remove completion effect. Evidence moderate for stage diagnosis; machine-reviewed excerpts and labels, single sample per cell, no human validation of passage sufficiency, fixed public corpus, not causal proof of internal evidence reliance. Compute H100/V100; paired replay costs extra inference but need only run on actual repeated defect.

Already/new: existing source-native retrieval, Claim Authority, uncertainty, correction and outcome-qualified Missions. New candidate matched-stage interventions: distinguish source found, exact passage delivered, prior revised, answer completed. A model's prior or host assertion is not automatically truth; source authority and subject/speaker scope must remain explicit, and deletion/permission filters apply before any delivery. Derived answers and trace caches are revocable/rebuildable.

Action: future only on a real correction or search completion failure. Hold authorized source and question constant, compare native retrieval against decisive-source delivery and answer-only control; fix failed stage, not backend by default. Do not introduce a generic evaluation campaign.

## 4. What Makes Good Data for Training Coding Agents? — reward-label correctness versus solvability

Primary: Zhang et al., arXiv:2611.30207v1, 23 November 2026. https://arxiv.org/html/2611.30207

Classification: **already covered/corroboration** with a specific conditional FBM training diagnostic. Distinct from gradient-aware successful-record selection (Nov23) and teacher trajectory quality: tests themselves can reward wrong behavior or reject right behavior.

Method: two LLM-family audits of SWE-Gym assertions and execution-confirmed witnesses; repair/remove false-negative tasks, identify passing incorrect patches with executed counterexamples, harden tests. Compare matched 512-task sets (original, pass-rate filter, audited, audited+hardened), Qwen3.5-9B GRPO, 80 steps x 16 tasks x 8 samples, three seeds, held-out repositories.

Evidence: 1,091/2,001 assertion-audited tasks receive false-negative verdict; 74% never-solved vs 20% sometimes-solved in Orig. 19.5% of gradient-carrying groups on sometimes-solved flawed tasks that survive pass-rate filtering. Clean vs Orig held-out Verified-397 62.6 vs 60.2%, Pro 56.2 vs 53.5%; pass-rate filtering does not improve mean. Clean+FP does not detectably improve held-out results; passing incorrect patches ~26.1% under conservative rule, many others undetermined. Audit repairs and replacements are jointly measured, one model/recipe, three seeds, residual benchmark errors possible. 168–401 GPU-hours per matched run, 8 GPUs, audit >=$1.30/task excluding unpriced agent calls. Moderate evidence for this RL setting, not proof current MFM labels are faulty.

Already/new: FBM already requires independent evaluator and source-bound target validity; MFM checkpoint10 authored structural controls already pass. Do not infer hidden reward flaw from 0/9 or change its objectives. New diagnostic if future reward-based lane shows stalled learning: check whether rejected but correct and accepted but wrong outputs receive gradient, using independently executed witnesses and unchanged contract. Preserve exact original targets, source rights, subject identity, audit/repair ancestry, deletion and rollback; no evaluator edits to manufacture qualification.

Action: only on demonstrated reward/target contradiction in a real FBM lane; no broad relabeling or new gate.
